# FlyMon 설계 문서 — 초파리 뇌(MaleCNS) + 코치가 1세대 OU 규칙 6대6 포켓몬 배틀을 한다

- 작성일: 2026-09-14
- 상태: 초안 v4 (v3 레드팀 17건 반영: 강화 신호 귀속, 인과 대조군, 탐색/확인 분리, 필터·배리어·체크포인트 규칙, 예산 축소, 풀 게이트)
- 작업 브랜치: `open-fly-brain-connectome`

## 0. 목표와 정확한 주장

**과제**: Pokémon Showdown 1세대 OU **규칙**의 6대6 배틀. 교체, 상태이상, 랭크 변화, 마비, 잔여 피해까지 Showdown 엔진이 처리한다. 단, **팀은 우리가 제약한 16종·제약 기술 풀**에서 뽑는다(3.2). 표준 OU 세트(바디슬램 마비 30%, 눈보라 빙결, 파괴광선, 잠듦기)는 v1에 없다. 따라서 이 과제는 "1세대 OU 메타"가 아니라 "1세대 OU 규칙 위의 제한 과제"다. README와 영상에 이 문장을 그대로 쓴다.

**역할 분담(하이브리드)**:
- **초파리 뇌**: MaleCNS v1.0 커넥톰(약 16만 뉴런) 전체 LIF 스파이킹 모델. 매 턴 "공격기 중 무엇을 쓸까"를 결정한다. 학습은 뇌 안의 실제 KC→MBON 시냅스(33,496개)에서 도파민 게이트 억제로만 일어난다.
- **코치**: 외부 정책. 교체할지, 보조기를 쓸지, 기절 뒤 누굴 낼지를 결정한다. v1은 poke-env SimpleHeuristicsPlayer 규칙(상성·속도·HP·랭크, 교체 판단). v2 후보는 Metamon 사전학습 에이전트.
- **결정 라우터**: 코치가 "공격"을 택했고 쓸 수 있는 공격기가 2개 이상이면 초파리가 고른다. 그 외는 코치. 매 턴 결정 주체를 기록·표시한다.

**1차 주장**: 초파리 뇌가 **같은 내 포켓몬·같은 후보 기술에서 상대 타입이 바뀌면 선택을 바꾸는** 상성 조건부 선호를 학습한다. 이 주장은 상대 타입 채널을 뺀 대조군(FLY-TB)과 가소성 끈 대조군(C-off)보다 나아야 성립한다(4.3 기준 1).

**2차 주장**: 그 선호가 실제 배틀 승률에 기여한다. 코치 + 무작위 공격기(RND)와의 승률 차이로 측정하고, 코치 자체의 공격 선택(MAX)을 상한으로 보고한다.

**정확히 구분해서 적을 것**:
- 학습되는 파라미터는 KC→MBON 가중치뿐. 초파리의 선택 규칙(MBON 가치 → softmax/argmax)에는 학습 상태가 없다. 코치는 학습하지 않는다.
- 관측 인코딩, 판독 집합, 도파민 펄스, 가중치 회복은 우리 설계 선택. 커넥톰이 주는 것은 연결·시냅스 수·신경전달물질 예측.
- 후각엽+버섯체 축소 회로는 탐색 전용. 최종 결과는 전체 뇌 실행으로만 인정.
- 초파리는 한 단계 가치 판단만 한다. 계획과 턴 간 신용 배분은 코치 몫이다.
- 대조군은 서로 **짝지어지지 않는다**(서버 난수 고정 불가). 같은 배틀 일정 파일을 쓰지만 각 팔은 다른 배틀을 겪는다. 통계는 마리→배틀 계층 부트스트랩으로 한다.

## 1. 사전 조사 요약과 근거

- 커넥톰 LIF에 도파민 가소성을 붙였을 때 냄새 특이적 학습이 나오지 않는 것을 두 프로젝트(fly-brain-bench, flybrain)가 기록했다. flybrain(MaleCNS, 단일 커밋, 라이선스 없음)은 원인을 고쳤고 수치를 FINDINGS.md에 남겼다. 우리는 그 설계 결정과 측정값을 **재현 목표**로 삼고 코드는 복사하지 않는다.
  - 후각엽 국소뉴런 lLN1/lLN2 억제성 재지정(151세포). APL 출력 스케일 0.1, kc_thresh 1.0~1.5 → 케니언세포 5% 활성, 설계된 두 냄새의 겹침 0.
  - MBON 기저 구동 0.85 → 기저 3.4 Hz. 도파민 구획은 DAN 타입별 DAN→MBON 직접 시냅스, 핵심 = 타입 최대의 0.2 이상. PPL105 → MBON13/18/23, PAM08 → MBON05/21, 겹침 없음.
  - 학습률 0.0003, DAN 70 mV, 냄새 강도 0.35(PN ~130 Hz), 800 ms. 8/8 시드 반전, 두 구획 독립 가산. 보상 채널이 학습 대부분을 옮긴다(보상만 −0.465, 처벌만 −0.088).
  - 알려진 한계: MBON05 포화, MBON18/21 침묵, 감소 전용 규칙과 바닥 20%. 폐루프 결정(verge_swarm)은 55생 뒤 가중치 변화 0.5%, 학습 개체와 순진 개체 차이 없음. **폐루프 정책 개선은 아직 아무도 보이지 못했다.** 1번 위험.
- 선행 게임 프로젝트는 네 부류다. 고정 매핑, 뇌 고정 + 외부 readout 학습, 뇌 안 가소성 시도(doomfly 실패, FlyPong 부정 결과, flybrain 성공), 부분 회로. 우리는 세 번째 부류에 코치를 얹은 형태다. "측정된 것 / 우리가 정한 것 / 안 된 것" 장부 구분을 따른다.
- Pokémon Showdown 본체(npm `pokemon-showdown` 0.11.11, MIT): 1세대 모드, 헤드리스 배틀(스모크 완료). 로컬 서버에 공식 웹 클라이언트를 붙이면 UI가 따라온다. 프로토콜은 잔여 피해를 `[from]` 태그로, 대타 피해를 `-activate`로 구분한다.
- poke-env 0.16.1(MIT, Python ≥3.10): 로컬 서버 클라이언트, 6대6 상태 파싱, `available_moves`, `damage_multiplier`, 동시 배틀, 비동기 `choose_move`, SimpleHeuristicsPlayer 내장. 턴별 원시 이벤트 접근은 M1에서 방법(observation events 또는 메시지 훅)을 확정한다.
- Metamon(MIT): 1세대 OU 사전학습 정책 40개 이상, 자체 서버 포크 필요. 코치 v2 후보.
- 1세대 룰(Showdown gen1 mod): 아이템·특성 없음, "특수" 단일 스탯, 급소율 = 종족 속도/512(고급소 /64), 모든 기술 1/256 빗나감, 빙결 영구, 잠듦 1~7턴, 팀 프리뷰 없음(선봉 = 팀 1번), 고스트→에스퍼 무효, 불→얼음 2배, 벌레↔독 2배.

## 2. 아키텍처

```
+-----------------------------+   websocket   +------------------------------+
| Node: pokemon-showdown 서버 | <-----------> | Python: poke-env             |
|  gen1ou, loopback 바인딩    |               |  FlyCoachPlayer (우리)       |
|  (사람은 공식 웹 클라이언트) |               |  상대: Random/Heuristic       |
+-----------------------------+               +---------------+--------------+
                                                              |
                          +-----------------------------------+------------------+
                          |  결정 라우터                                          |
                          |  코치 주문 = 공격기 & 공격기 후보 ≥ 2 → 초파리        |
                          |  그 외(교체·보조기·강제 교체·후보 1개) → 코치          |
                          +--------+---------------------------------+----------+
                                   |                                 |
                     후보 냄새(≤4) |                                 | 코치 주문
                                   v                                 v
                   +------------------------------+          (그대로 서버로)
                   | 뇌 풀 fly_pool.py            |
                   |  워커 W개, 마리별 가중치 스왑 |
                   |  후보 4개 같은 시드로 순차 제시|
                   |  판독 → V(후보) → softmax     |
                   |  강화: PAM08 / PPL105        |
                   +------------------------------+
   원시 프로토콜 → 귀속 파서 → 강화 신호
   로그(JSONL) + 체크포인트(2세대 + manifest) → analyze.py → results/ → web/ · 영상
```

한 턴의 순서:
1. poke-env가 배틀 상태를 준다. 코치가 주문을 계산한다.
2. 라우터: 코치 주문이 공격기이고 `available_moves` 중 공격기가 2개 이상이면 초파리 차례. 아니면 코치 주문 전송. 결정 주체 기록.
3. 초파리 차례: 후보(≤4)를 냄새로 만들어 그 마리의 워커에서 같은 시드로 순차 제시(가중치 공유, 같은 잡음). 읽기 구간의 판독 MBON 발화로 V 계산. softmax(V/τ)로 선택. 평가 모드는 argmax, 가소성 끔.
4. 서버가 턴을 처리한다. **귀속 파서**(3.4)가 원시 프로토콜에서 내 기술의 직접 피해·상성·기절을 귀속한다.
5. 강화(초파리가 결정했고 귀속이 확실한 턴만): 선택한 냄새를 재제시하며 DAN 70 mV 구동.
6. 배틀 종료 시 체크포인트.

**배치 배리어**: 코호트의 F마리는 각자 poke-env 플레이어로 동시에 배틀한다. 초파리 차례가 오면 비동기 `choose_move`가 배리어에 요청을 넣고 기다린다. 배리어는 다음 중 먼저 오는 조건에서 실행한다: (a) 첫 요청 도착 후 wall-clock 100 ms 경과, (b) 현재 **활성**(배틀 진행 중이고 예외가 없는) 플레이어 전원이 대기. 실행 시 대기 중인 요청만 모아 풀에 나눠 보내고 각자에게 결과를 돌려준다. 배틀 종료·예외·취소된 플레이어는 활성 집합에서 즉시 제거하고, 그 플레이어의 대기 요청은 취소 예외로 깨운다. 테스트: 배틀 1개만 잔존, 중도 예외, 마감과 신규 요청 경쟁, 전원 종료.

## 3. 구성 요소

### 3.1 뇌 엔진 (`flymon/brain/`) — 자체 구현, MIT

- **데이터 빌드** `data_build.py`: Janelia MaleCNS v1.0 세 feather 파일(가중치 1.1 GB, 주석 13 MB, 신경전달물질 42 MB, CC-BY 4.0, neuPrint 로그인 필요) → 우리 npz. 뉴런: bodyId, type, class, superclass, nt, sign, side. 엣지: pre, post, w. 글루탐산·히스타민 억제. lLN1/lLN2 억제 재지정은 설정 파일에 명시. 반구 불균형은 후시냅스 가중치 스케일링으로 보정. 미러링은 v1 범위 밖. 원본 파일 해시를 문서에 기록.
- **CPU 엔진** `engine_cpu.py`: Shiu et al. 2024 상수(휴지 −52 mV, 역치 −45, τm 20 ms, τsyn 5 ms, 지연 1.8 ms, 불응 2.2 ms, 0.275 mV/시냅스), α-시냅스, dt 1 ms, 이벤트 구동. 수용체는 포아송 소스. APL 스케일, MBON 기저 구동, KC 역치 정규화를 파라미터로. 검증 기준 구현.
- **프로세스 풀 스웜** `fly_pool.py` + `presentation.py`: 워커 프로세스 W개(기본 16)가 각자 CPU `Engine`+`Plasticity` 하나를 들고 마리 F개의 요청을 나눠 맡는다. 막 상태는 프레젠테이션마다 리셋되므로 마리별로 남는 것은 KC→MBON 가중치·켬/끔 플래그·배선 변형뿐이고, 요청은 그 마리의 가중치를 싣고 가서 워커의 CSC에 써넣고 돌아온다(hive = 마리 하나에 가중치 하나, 부모 프로세스가 보관). 결정은 후보 ≤4개를 같은 시드로 순차 제시(짝지은 잡음), 강화는 M0 `train_block`의 한 프레젠테이션과 같다. 마리별 플래그: 가소성 켬/끔, KC→MBON 셔플 시드(`connectome.shuffle_kc_mbon`); DAN 구동 여부는 호출자가 정한다. 상태 왕복(`state`/`load_state`). MPS 배치 엔진은 레드팀에서 CPU 풀보다 느리고 복잡한 것으로 판정돼 채택하지 않았다(부록 C.6).
- **회로 정의** `circuits.py`: 인구 인덱스, 도파민 구획 표(JSON, README 수록).
- **가소성** `plasticity.py`: `w *= 1 − lr·tanh(KC자취 × 위상성DA)`, 바닥 0.2. **추가(우리 선택)**: 느린 회복 `w += (w0 − w)·dt/τ_rec`. τ_rec는 **펄스 수 기준**으로 정한다(예: 펄스 1,000회 뒤 중앙값 ≥ 0.5). 값은 M2 탐색 세트에서 정하고 동결한다.
- **판독** `readout.py`: 접근 집합 A(PPL1 계열 핵심 표적이며 반응하는 MBON), 회피 집합 P(PAM 계열 핵심 표적이며 반응하는 MBON). V = z_A − z_P. z의 기준 평균·표준편차는 **탐색 세트**(4.4)의 후보 냄새를 순진 뇌에 제시해 구하고 동결. d′ = 짝지은 잡음 반복(8회)에서 V 차이의 평균/표준편차.
- **인코더 변형 플래그**: `type_blind=True`면 상대 타입 채널을 끈다(대조군 FLY-TB).

### 3.2 배틀 환경 (`flymon/battle/`)

- **서버**: `pokemon-showdown@0.11.11` 고정. `config.js`에서 `bindaddress`를 127.0.0.1로 고정, 외부 바인딩은 명시 옵션. 시작 스크립트에 포트 점유 확인, 종료 처리, 임시 계정·로그 정리. 포맷 `gen1ou`.
- **플레이어** `fly_coach_player.py`: poke-env `Player` 서브클래스. 코치·라우터·초파리 호출·강화·로그. 상대: `RandomPlayer`, `SimpleHeuristicsPlayer`. 배틀 일정(내 팀과 **팀 순서**, 상대 팀과 순서, 상대 정책 종류)은 파일로 미리 생성해 모든 팔이 공유한다. 서버 난수와 상대 RNG는 고정되지 않는다.
- **코치** `coach.py`: v1 = SimpleHeuristicsPlayer 규칙을 함수로 감싼 것. 주문이 공격기인지 판정하는 인터페이스. **약한 코치**(`weak=True`): 강제 교체 외에는 교체하지 않고 보조기도 쓰지 않는다(기여도 측정용). 스탯 추정이 3세대 이후 공식(+31 IV)이라 1세대에서 근사임을 README에 명시. v2 = Metamon(백로그).
- **MAX 정의**: 코치 자체의 공격 선택(위력 × 자속 × 상성 점수). 별도 데미지 계산기 없음.
- **팀 풀** `pool.py` + `validate_pool.py`: 1세대 OU 합법 16마리, 각 공격기 2~3개 + 코치용 보조기 1~2개. 배틀마다 양쪽이 풀에서 6마리와 순서를 시드로 뽑는다. 검증 스크립트는 기술별 허용·거부 사유를 출력한다.
  - **초파리 후보 공격기 허용 목록**(Showdown 기술 데이터 필드로 판정): category ∈ {Physical, Special}, basePower > 0, accuracy ≥ 90, critRatio = 1, flags에 charge·recharge 없음, recoil 없음, selfdestruct 없음, volatileStatus ≠ partiallytrapped, lockedmove 아님, `damage` 필드 없음(고정·레벨 피해 제외), secondary가 없거나 {status ∈ {par, brn, psn}이고 chance ≤ 10} 또는 {boosts 하락이고 chance ≤ 33}. 빙결·잠듦·혼란 부가효과는 거부. 예시 허용: 파도타기, 폭포오르기, 지진, 뼈다귀부메랑, 드릴부리, 날개치기, 덩굴채찍, 메가드레인, 스피드스타, 더블킥, 스톤샤워, 사이코키네시스, 10만볼트, 화염방사, 오로라빔, 트라이어택. 예시 거부: 대폭발, 자폭, 조이기, 감기기, 난동부리기, 파괴광선, 공중날기, 눈보라, 냉동빔, 바디슬램, 베어가르기.
  - 같은 마리의 공격기는 타입이 서로 다르다. 종족 속도 ≤ 100.
  - **코치용 보조기 허용**: 전기파, 리플렉터, 빛의장막, 회복(리커버·알낳기), 랭크업(칼춤·드러눕기). **거부**: 대타, 맹독, 혼란 유발기, 잠듦기, 구속기, 폭발기, 잠자기.
  - gen1ou TeamValidator로 합법성 확인. 풀 전체 타입 수 ≤ 12.
- **후보 추출**: `available_moves` 중 위력 > 0인 기술 전부. 풀의 공격기는 모두 허용 목록을 통과했으므로 "쓸 수 있는 공격기 = 초파리 후보"이고, 코치가 고른 공격기는 항상 후보 안에 있다. 최대 4개.

### 3.3 인코더 (`flymon/brain/odors.py`)

- 채널 = 후각 수용체 타입. DA1(cVA)과 V(CO2) 제외, 51개 중 최대 45개: 내 타입(≤12), 상대 타입(≤12), 기술 타입(≤12), 위력 구간 3(<60, 60~89, ≥90), 내 HP 구간 3, 상대 HP 구간 3.
- 후보 냄새 = {내 타입1(,2), 상대 타입1(,2), 기술 타입, 위력 구간, 내 HP, 상대 HP} → 사구체 6~9개. `type_blind`면 상대 타입 채널 생략.
- 드라이브 균등화: 채널 강도 ∝ 1/수용체 수, 제시 강도 0.35. PN 발화율 편차 ±20% 이내.
- 같은 턴 후보는 기술 타입·위력 채널만 다르다. KC 결합 코드와 MBON 수준 분리를 M2에서 측정한다.

### 3.4 강화 신호와 귀속 파서 (초파리가 결정한 턴만)

**귀속 규칙**(원시 프로토콜, 행동 단위):
- `|move|<내 활성>|<기술>|<대상>` 다음 줄부터 다음 `|move|`·`|turn|`·`|upkeep|` 전까지를 그 행동의 이벤트 블록으로 본다.
- 블록 안의 `|-damage|<대상>|HP` 중 `[from]`이 **없는** 것만 직접 피해. `[from] brn/psn/confusion/Wrap …`은 잔여 피해로 무시.
- `|-activate|<대상>|Substitute|[damage]`는 대타 피해: 직접 피해 0, 무신호(v1 풀에는 대타가 없지만 파서는 처리한다).
- `|faint|<대상>`이 직접 피해 바로 뒤에 오면 기절을 내 기술에 귀속. 잔여 피해 뒤에 오면 귀속하지 않는다.
- `|-miss|`, 풀마비·행동 불가(`|cant|`)는 무신호.
- 상성 배율은 프로토콜 태그(`-supereffective`, `-resisted`, `-immune`)와 `damage_multiplier` 계산을 둘 다 구해 불일치하면 로그에 남기고 무신호.
- 귀속이 불확실한 블록(순서가 어긋남, 대상 식별 실패)은 무신호.
- d = min(직접 피해, 대상 타격 전 현재 HP) / 대상 최대 HP.

| 결과 | 채널 | 펄스 |
|---|---|---|
| 직접 피해 비율 d > 0 | PAM08 | 400·d ms |
| 상성 배율 < 1 (`-resisted`) | PPL105 | 200 ms |
| 상성 배율 0 (`-immune`) | PPL105 | 400 ms |
| 귀속된 대상 기절 | PAM08 | +200 ms |
| d = 0이고 태그 없음, 빗나감, 행동 불가, 불확실 | 없음 | 무신호(강화 단계 생략) |

받은 피해와 배틀 승패는 쓰지 않는다. 프로토콜: 선택한 냄새를 슬롯 0에 제시, 안정화 뒤 펄스 구간 동안 DAN 70 mV, 다른 슬롯 무자극.

**M1 통합 테스트**: 화상 잔여 피해 뒤 기절, 대타 타격, 빗나감, 동시 기절(양쪽), 교체 턴, 상성 태그와 계산 불일치 각각에 대해 파서 출력을 고정 로그로 검증.

### 3.5 결정 규칙과 탐색

- 학습 중 softmax(V/τ), τ는 배틀 인덱스 함수로 1.0 → 0.2 선형(첫 20배틀). 학습 상태 없음.
- 평가: argmax, 가소성 끔.

### 3.6 학습 루프, 체크포인트, 로그

- 코호트: F마리, 워커 W개(기본 16). 각 마리는 poke-env 플레이어 하나, 자기 일정.
- **체크포인트**: 배틀 종료마다 가중치 [F, E](fp16), 회복 상태, 엔진 RNG, 일정 커서, 설정 해시를 임시 파일에 쓰고 rename. **2세대 보관** + manifest(체크섬, 스키마 버전, 완료 배틀 ID 목록). 로그의 각 배틀 레코드는 같은 배틀 커밋 ID를 가진다. 재개 시 manifest의 완료 ID를 건너뛰고, 체크섬 실패면 직전 세대로 돌아가며 그 이후 로그 레코드는 버린다. 강제 종료 지점(가중치 저장 중, manifest 갱신 전, 로그 기록 중)별 재개 테스트.
- 로그(JSONL): 턴마다 결정 주체, 코치 주문, 후보 V, 선택, 귀속 결과, 펄스, 판독 발화 수, KC 활성 수. 배틀마다 구획별 가중치 비율, 승패, 초파리 결정 턴 수, 무신호 턴 수. 스파이크 래스터는 시연 플래그 배틀만.

### 3.7 공개물

- **뷰어**(`web/`, 정적): 턴별 "초파리/코치" 배지, 후보 가치 막대, 버섯체 래스터(시연 배틀), 구획별 가중치 변화, 팔별 학습 곡선과 절제 비교. 스프라이트 없음.

**REV 반전표**: d → PPL105 400·d ms, 상성 < 1 → PAM08 200 ms, 무효 → PAM08 400 ms, 귀속 기절 → PPL105 200 ms.

### 4.2 고정 정책 평가

10배틀마다 가소성·탐색을 끄고 **확인 세트**(4.4)에서 평가한다.
- **타입 조건부 전환율(1차)**: 확인 세트의 상황 쌍 {같은 내 포켓몬, 같은 후보 4개, 상대 타입만 다름}에서 두 상황의 최적 기술이 다를 때, 초파리가 두 상황 모두에서 최적을 고른 비율.
- **정보 있는 턴 상성 일치율**: 후보들의 최대 배율이 서로 다른 턴에서 최대 배율 기술을 고른 비율. 정보 있는 턴의 비율도 보고.
- **승률**(코치 영향 포함).

### 4.3 사전 등록 성공 기준

1. **(1차)** 40배틀 시점 FLY의 타입 조건부 전환율이 C-off보다, 그리고 FLY-TB보다 각각 0.15 이상 높고, 마리→배틀 계층 부트스트랩 95% CI가 0을 제외.
2. **(2차)** FLY의 정보 있는 턴 일치율 > C-off, 같은 통계.
3. **(2차, 기여도)** FLY 승률 > RND 승률, 같은 통계. MAX와 WEAK 팔은 상한과 보조로 보고.
4. **(채널·배선 특이성)** C-PAM < FLY. FLY-RS와 C-shuf는 C-off와 유의하게 다르지 않아야 한다. C-PPL은 탐색 보고.
5. **(반전)** REV 15배틀 뒤 확인 세트 상황 쌍의 ΔV 부호가 FLY 종료 시점 대비 반전(마리 단위 부호 검정).

**안전 제약(성공 기준이 아니며 위반 시 실행을 멈추고 보고)**: 비가소성 가중치 비트 동일(mutation test), 결정 규칙 무상태(테스트), 코치 결정 턴의 DAN 구동 0(테스트), 가소성 가중치 중앙값 ≥ 0.5.

기준 1을 못 넘으면 "타입 조건부 학습 안 됨"으로 보고한다. 사후 조정 없음. 최소 검출 효과 0.15와 마리 수는 M1 파일럿(RND·MAX 분산)으로 검정력을 계산해 M2 종료 전에 확정·동결한다.

### 4.4 탐색 세트와 확인 세트

- **탐색 세트**: 판독 집합·창 길이·펄스·τ_rec·정규화 기준을 정하는 데 쓰는 상황(팀 조합·상대 타입·후보 집합)과 시드. M2에서만 사용.
- **확인 세트**: 고정 정책 평가와 성공 판정에 쓰는 상황 쌍 20개 이상과 배틀 20개. 탐색 세트와 팀 조합이 겹치지 않는다.
- M2 종료 시 모든 파라미터를 설정 파일에 동결하고 해시를 기록한다. M4는 새 시드로 실행한다.

## 5. 마일스톤과 게이트

- **M0 엔진과 재현**: 스캐폴드(uv, Python 3.13, Node 24, pytest). 데이터 빌드와 해시. CPU 엔진. flybrain 측정값 재현: KC 활성 5%±2, Jaccard ≤ 우연, MBON 기저 3~4 Hz, **조건화 반전 8/8 시드**(엔진 합격 기준). 병행: flybrain 저자에게 감사·라이선스 이슈.
- **M0b 프로세스 풀 스웜**: 프레젠테이션 프로토콜(결정·강화), 워커 풀, 짝지은 잡음, hive, 마리별 팔 플래그, 상태 왕복 API. 등가성: 워커의 결정이 같은 시드의 인프로세스 `Engine`과 카운트 동일, M0 조건화 5팔 × 8시드를 풀로 재실행해 `results/m0/conditioning.json`과 시드별 비트 동일. 처리량(워커 4/8/16, 결정·강화 단계, 반복 측정). 4.1 학습 결정 수와 4.2 평가 결정 수로 외삽한 예산표를 부록 C에 기록. **게이트: 전체 ≤ 60시간**, 아니면 4.1 축소 순서 적용. 휴지 100 Hz 초과 집합의 KC 수와 스파이크 비율도 기록한다(STD 재검토 조건, 부록 A.5).
- **M1 배틀 환경**: 서버 설치·loopback 스크립트, FlyCoachPlayer(코치·라우터·배리어), 귀속 파서, 팀 풀 허용 목록과 검증 출력, 일정 생성기(팀 순서 포함). 테스트: 라우터 판정, 후보 추출과 냄새 유일성, 배리어(잔존 1개·예외·경쟁·전원 종료), 귀속 파서 6개 사례, 일정 재현성. **파일럿(뇌 불필요)**: RND·MAX·WEAK-RND·WEAK-MAX 각 100배틀. **게이트: MAX − RND 승률 ≥ 0.15**, 아니면 풀 재설계(마리당 타입 다양성 확대, 코치 교체 조건 완화) 후 재측정. 파일럿 분산으로 검정력 계산.
- **M2 인코더·판독·학습 단위 시험(go/no-go)**: 탐색 세트에서 채널 균등화, 후보 KC 활성 5~9%, 같은 턴 후보의 MBON 분리, 공통 채널만 바꿨을 때 순위 보존율, 판독 집합 선정, 창 길이 수렴, τ_rec(펄스 수 기준). **학습 단위 시험**: 순진 뇌 d′ ≈ 0, 보상 20회 뒤 d′ ≥ 1, 처벌 20회 뒤 하락. 종료 시 파라미터 동결·해시. 실패하면 멈추고 보고.
- **M3 에이전트 루프**: 초파리 결정·강화를 FlyCoachPlayer에 연결, 체크포인트 2세대·manifest·재개 테스트, 로그 스키마, F=2 배틀 2 스모크, 안전 제약 테스트 4개.
- **M4 실험**: 4.1 팔을 예산 순서로, 고정 정책 평가, 분석, 결과 JSON·그림.
- **M5 공개물**: 뷰어, README, 영상. 사람 대전은 봇 계정 챌린지 대기 스크립트(loopback 서버).
- **v2 백로그**: 초파리가 교체 대상 선택, Metamon 코치, 표준 OU 세트 허용, 뇌 특징 + PPO 팔, 브라우저 축소 버섯체 시연, 시드 고정이 꼭 필요하면 인프로세스 BattleStream + poke-env 파서 직접 공급 경로.

또는 M0b가 재는 휴지 100 Hz 초과 집합에 KC가 포함될 때. 넣는다면 전시냅스 뉴런별 Tsodyks–Markram(시냅스별 상태 [B, 6 M]은 배치에서 비현실적)이며,
M0 게이트 재실행과 CPU–MPS 일치·처리량 재측정이 따른다.

## 부록 B. M1 파일럿 결과 (2026-09-14)

**결과: 통과(PASS).** MAX − RND 승률 = **0.319**, 마리 단위 부트스트랩 95% CI [0.291, 0.344] (2,000회, seed 0) ≥ 0.15.
요약 `results/summary/m1_pilot.json`, 일정 `results/summary/schedule_m1.json`. 팔별 원본과 턴 로그는 `results/m1/`(git 제외).

### B.1 설정

- `pokemon-showdown` 0.11.11(npm, loopback 127.0.0.1, `--no-security`), poke-env 0.16.1, 포맷 `gen1ou`.
- 풀 16마리(`docs/pool.md`). 계획의 제안 로스터가 허용 목록과 `validate-team gen1ou`를 **교체 없이** 전부 통과했다.
  공격기 타입 8종(≤ 12), 종족 속도 ≤ 100, 마리당 공격기 2–3개(타입 서로 다름) + 보조기 0–2개.
- 일정: seed 0, 16마리 × 100배틀, 양쪽 팀 6마리를 풀에서 비복원 추출(순서 포함, 1번이 선봉), 상대는 모든 배틀에서
  `SimpleHeuristicsPlayer`. 네 팔이 같은 일정 파일을 쓰지만 서버 난수는 고정되지 않는다(0절).
- 팔: RND(무작위 공격기, 코치 v1) · MAX(코치 점수 최대 공격기 = 코치 자체 선택) · WEAK-RND · WEAK-MAX(약한 코치:
  강제 교체 외 교체 없음, 보조기 없음). 라우터: 코치 주문이 공격기이고 후보 ≥ 2이면 제공자, 그 외 코치.

### B.2 팔별 결과 (팔당 1,600배틀, 동점 0, 미완료 0)

| 팔 | 승률 | 마리 간 SD | 이항 하한 SD(100배틀) | 제공자 결정 비율 | 후보 수 평균 | 벽시계 |
|---|---|---|---|---|---|---|
| RND | 0.152 | 0.029 | 0.036 | 0.826 | 2.48 | 33 s |
| MAX | 0.471 | 0.050 | 0.050 | 0.821 | 2.47 | 501 s |
| WEAK-RND | 0.145 | 0.033 | 0.035 | 0.834 | 2.47 | 308 s |
| WEAK-MAX | 0.485 | 0.040 | 0.050 | 0.829 | 2.47 | 449 s |

"제공자 결정 비율"은 결정 레코드 중 `decider == "fly"`인 비율이다(강제 교체는 같은 턴에 결정 레코드를 하나 더 만든다).

### B.3 관찰

- **마리 간 분산은 이항 하한과 같다.** 마리 수준 추가 분산 추정치 ≈ 0.00004. 마리는 사실상 교환 가능하다.
- **약한 코치 ≈ 강한 코치.** WEAK-MAX 0.485 vs MAX 0.471, WEAK-RND 0.145 vs RND 0.152. 이 풀에서 코치의 교체·보조기는
  승률에 기여하지 않고, 공격기 선택만으로 0.32의 차이가 난다. 초파리 기여도 측정(4.3 기준 3)에 잡음 원천이 적다는 뜻이다.
- **RND가 0.15에 그치는 이유.** 상대 `SimpleHeuristicsPlayer`는 같은 풀에서 MAX와 같은 규칙으로 공격기를 고르므로
  RND는 상대보다 체계적으로 약하다. MAX 0.47–0.49는 대칭 매치업(≈ 0.5)과 맞는다.
- **벽시계 편차(33–501 s).** 턴 수(팔 평균 22–25)로 설명되지 않고 잔존 서버도 없었다. 원인 미확인이며 게이트 기준이 아니다.
  M3 스모크에서 팔별 벽시계를 다시 잰다.

### B.4 검정력 (4.3 기준 3, 파일럿 분산 기반)

FLY(12마리 × 40배틀) 대 RND(16 × 100), MDE 0.15, 양측 α = 0.05, 마리 수준 추가 분산 = 파일럿 추정치:
SE(차이) ≈ 0.023 → 검정력 ≈ 1.0. 80% 검정력에서의 MDE ≈ 0.064. 즉 마리 수 12/16과 MDE 0.15는 여유가 크다.
이 값은 **승률 기준(3)에 대한 것**이다. 1차 기준(타입 조건부 전환율)의 분산은 초파리 결정 없이 잴 수 없어
M2 학습 단위 시험 뒤에 계산한다. MDE·마리 수의 최종값은 4.3대로 M2 종료 전에 확정·동결한다(여기서는 선택지만 기록).

### B.5 M1에서 확정된 구현 사실

- poke-env 0.16.1에는 `Battle.observations`가 없다. 원시 프로토콜은 `Player._handle_battle_message` 오버라이드로 받는다(9절 미결 해소).
- 승리 턴은 `|faint|` → `|win|`으로 끝나고 `|upkeep|`이 없다. 귀속 파서의 마지막 블록은 `|win|`/`|tie|`에서 닫는다.
- 턴 로그(JSONL)는 결정 레코드(`kind: "decision"`)와 결과 레코드(`kind: "outcome"`)를 분리하고 `(battle_tag, turn)`으로 잇는다.
  강제 교체가 있는 턴은 결정 레코드가 둘이다(다대일 결합).
- 귀속 파서는 3.4의 6개 사례에 동시 기절·상성 태그/계산 불일치를 더해 고정 로그 13개로 검증했다. 다단 히트는 첫 타격 전 HP 기준,
  `-hitcount`/`-message` 같은 장식 줄은 기절 인접성을 끊지 않는다.
- 배치 배리어는 잔존 1명이면 즉시 실행(2절 조건 b), 진행 중 배치의 요청도 취소로 깨우며, `run_batch` 결과 길이 불일치는 대기자 전원에게 예외로 전파한다.

## 부록 C. M0b 설계 결정과 스파이크 측정 (2026-09-15)

**2026-09-15 갱신**: C.1–C.5는 MPS 배치 엔진 설계와 그 측정의 기록이다. 계획 레드팀에서 기존 CPU 엔진의 프로세스 풀이 더 빠르고 단순하다는 것이 실측으로 드러나 C.6대로 전환했다. C.1–C.5는 고치지 않고 남긴다.

STD 보류(A.5)와 M0b 범위 확정 뒤, 계획을 쓰기 전에 폐기용 스크립트로 torch MPS의 실행 가능성과 처리량을 쟀다.
스크립트와 결과 JSON은 세션 스크래치에만 있고 저장소에는 없다. M0b의 `scripts/bench_mps.py`가 같은 측정을
`results/summary/m0b_bench.json`으로 다시 남기며, 그 값이 이 부록의 숫자를 대체한다.

### C.1 결정

- **STD 보류**(A.5). M0b는 동결된 M0 엔진 동역학을 그대로 배치화한다.
- **범위**: 5절 M0b 항목 + 마리별 팔 플래그(가소성 켬/끔, KC→MBON 셔플 시드, DAN 구동) + 잡음 소스 주입 + 상태 왕복 API.
  플래그 덕에 4.1의 FLY, C-off, C-PAM, C-shuf, C-PPL이 한 스웜에 섞이므로 예산은 팔 순차가 아니라 동시 실행 기준이다.
- **백엔드**: torch 2.14, MPS. 주 의존성으로 추가. 엔진은 `device="cpu"`로도 돌아 torch만 있으면 테스트가 어디서나 실행된다.
  MLX는 torch 측정이 충분해 비교하지 않았다.
- **범위 밖**: 인코더 `odors.py`와 판독 `readout.py`(M2), 체크포인트 파일·재개(M3), 배리어 `run_batch` 연결(M3).

### C.2 엔진 설계

1. **전파 두 갈래.** 공유 CSC(KC→MBON 제외 5,972,115 엣지)는 지연선에서 도착한 (슬롯, 뉴런) 쌍의 out-edge를
   `repeat_interleave`로 펼쳐 `index_add_`로 [B·N] 전도도에 더한다. KC→MBON 33,496 엣지는 마리별 밀집 행렬
   W[F, 4064, 97]로 두고 도착한 KC 스파이크 행렬 [F, 4, 4064]와 bmm한다. 초기값은 CSC의 보정된 mV 값이고 W0 = 0인 칸은 마스크로 영구 0.
2. **상태.** v, g [B, N] float32, refrac [B, N] int32, 지연선은 `dly_steps()`개의 (슬롯, 뉴런) 쌍, 수용체 drive_hz는 슬롯별 [B, R],
   ext는 [B, N](MBON hold 공유 + 마리별 DAN 구동). 방정식·지연·불응기 회계·막전위 하한은 CPU 엔진(3.1)과 같다.
3. **짝지은 잡음.** 막 잡음 [F, N]과 수용체 균일 난수 [F, R]을 뽑아 4배 반복한다. 같은 냄새를 넣은 한 마리의 4슬롯은 스파이크가 정확히 같다.
   잡음 소스는 호출 가능 객체로 주입할 수 있어 테스트는 CPU 엔진과 같은 numpy 생성기를 넣는다. 장치 생성기 상태는 `get_state`/`set_state`로 왕복한다(MPS에서 확인, 44바이트).
4. **가소성.** 규칙은 3.1과 같고 형태만 외적이다. KC 자취 [F, 4064]와 도파민 자취 [F, 97]은 각 마리의 **슬롯 0**에서만 쌓인다(강화 슬롯).
   갱신 `W *= 1 − lr·tanh(자취 외적)`은 마리별 플래그로 끄고, 바닥 0.2·W0과 마스크를 지킨다. `recover_pulse`, `reset_weights`, `weights_frac`는 마리 인자를 받는다.
5. **API(M3 계약).** `SwarmEngine(conn, pops, params, n_flies, seed, device)`. 슬롯별 `present(slot, odor, strength)`·`clear_drive(slots)`,
   마리별 `drive_dan(fly, type, mv)`·`quiet_dan(fly)`, `run(ms) -> counts[B, N]`, `reset(seed)`, `plasticity.enabled[F]`·`weights[F, n_KC, n_MBON]`,
   `state()`/`load_state(d)`(가중치, 생성기 상태, 시각, numpy). 배리어의 `run_batch`는 M3가 이 위에 얹는다.

### C.4 예산 외삽 (가정 명시)

### C.5 M0b 테스트

1. 합성 망 래스터 동일: 주입 소스가 CPU `Engine.step`과 같은 순서로 `standard_normal(N, float32)`·`random(R)`을 한 생성기에서 뽑을 때,
   슬롯 0의 (t, 뉴런) 스파이크가 300스텝 동안 CPU와 정확히 같다. 잡음 0에서도 같다. CPU의 bincount는 float64 누적 뒤 float32 변환이라
   막전위는 마지막 비트에서 다를 수 있으므로 비교 대상은 래스터다.
2. 짝지은 슬롯: 같은 냄새를 넣은 4슬롯의 카운트가 동일하고, 다른 냄새면 다르다.
3. 마리 격리: 마리 0에만 DAN 펄스 → W[0]만 변하고 나머지는 비트 동일.
4. 플래그: 가소성 끔이면 W 불변, 셔플 시드는 W0의 값 다중집합을 보존한 순열.
5. 상태 왕복: `state`/`load_state` 뒤 이어지는 100스텝의 스파이크가 원본 계속 실행과 같다.
6. 실제 데이터(없으면 skip): 희소성 KC 활성 |Δ| ≤ 0.01, Jaccard ≤ 우연, MBON 절사 기저 3–4 Hz. 조건화 5팔 × 8시드를 마리 40개 스웜 한 번으로 돌려
   채널별 특이 억제 8/8(A.2 정의) 재현. 휴지 100 Hz 초과 집합의 KC 수와 스파이크 비율 기록.
7. 처리량: `bench_mps.py`가 B=32/64/128/256 가소성 켬 ms/step과 C.4 표를 `results/summary/m0b_bench.json`에 쓴다.

### C.6 레드팀 후 전환 (2026-09-15): MPS 배치 엔진 → CPU 프로세스 풀

계획은 "처리량을 위해 MPS가 필요하다"고 전제했지만 이미 있는 CPU `Engine`을 프로세스 풀로 돌리는 대안을 재지 않았다. 재 보니 다음과 같다

MPS B=128는 가소성 켬 4.35, 끔 5.9 슬롯-스텝/ms였다(C.3). 게다가 CPU 경로는 유휴 슬롯을 돌리지 않아 결정 하나가

**결정**: M0b는 CPU 프로세스 풀 스웜(3.1)으로 만든다. torch는 넣지 않는다. 등가성 게이트는 통계 일치 대신 두 가지 정확 일치로 바꾼다:
워커의 결정이 같은 시드의 인프로세스 엔진과 카운트 동일, M0 조건화 5팔 × 8시드의 풀 재실행이 `results/m0/conditioning.json`과 시드별 비트 동일.

레드팀의 나머지 지적(상태 왕복 테스트의 실효성, 슬롯 필터, `run(ms)` 단위, 데이터 없을 때의 종료 코드)은 새 계획에 반영한다.
