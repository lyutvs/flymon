# FlyMon 설계 문서 — 초파리 뇌(MaleCNS)가 포켓몬 배틀을 배우게 하기

- 작성일: 2026-09-14
- 상태: 초안 v2 (레드팀 리뷰 18건과 Showdown 룰북 확인을 반영)
- 작업 브랜치: `open-fly-brain-connectome`

## 0. 한 줄 목표와 정확한 주장

**주장할 수 있는 것**: MaleCNS v1.0 수컷 초파리 중추신경계 커넥톰(약 16만 뉴런) 전체를 LIF 스파이킹 모델로 돌리고, 배틀 상황을 냄새로 제시했을 때, 뇌 안의 실제 KC→MBON 시냅스(33,496개)가 도파민 게이트 억제로만 바뀌면서 상성에 맞는 기술을 고르는 선호가 형성된다.

**정확히 구분해서 적을 것**:
- 학습(가소성)은 뇌 안에서만 일어난다. 학습되는 파라미터는 KC→MBON 가중치뿐이다.
- 행동 선택은 학습되지 않는 고정 규칙이다. 후보 4개의 MBON 가치를 읽어 소프트맥스(평가 시 argmax)로 고른다. 이 규칙에는 학습 상태가 없다.
- 후각엽+버섯체 축소 회로는 탐색 실험 전용이다. 최종 결과는 전체 뇌 실행으로만 인정한다.
- 관측 인코딩(상태→냄새), 판독 집합, 도파민 펄스 길이, 가중치 회복은 우리의 설계 선택이다. 커넥톰이 주는 것은 연결과 시냅스 수, 신경전달물질 예측이다.

## 1. 사전 조사 요약과 근거

- 두 독립 프로젝트(fly-brain-bench, flybrain)가 커넥톰 LIF에 도파민 가소성을 붙였을 때 냄새 특이적 학습이 나오지 않음을 기록했다(케니언세포 60~75% 활성, 냄새 간 99% 겹침).
- flybrain(TheMrRaGe, MaleCNS, 단일 커밋, 라이선스 없음)은 원인을 찾아 고쳤고 결과를 FINDINGS.md에 수치로 남겼다. 우리는 그 문서의 설계 결정과 측정값을 **재현 목표**로 삼는다. 코드는 복사하지 않는다.
  - 후각엽 국소뉴런 lLN1/lLN2를 억제성으로 재지정(151세포). 냄새 하나가 53개 사구체 중 1개만 켜게 됨.
  - 실제 APL 뉴런 출력 스케일 0.1, kc_thresh 1.0~1.5 → 케니언세포 5% 활성, 설계된 두 냄새의 겹침 0(우연 수준 이하).
  - MBON 기저 구동 mbon_hold_frac 0.85 → MBON 기저 3.4 Hz, 핵심 구획 MBON이 냄새에 반응.
  - 도파민 구획을 타입별 DAN→MBON 직접 시냅스로 정의, 핵심 = 타입 최대의 0.2 이상. PPL105 → MBON13/18/23, PAM08 → MBON05/21. 두 집합은 겹치지 않는다.
  - 학습률 0.0003, DAN 자극 70 mV, 냄새 강도 0.35(PN ~130 Hz), 800 ms 제시. 8/8 시드에서 보상·처벌 반전 시 선호 반전, 두 구획이 독립적으로 가산(−1.492 vs −1.493). 학습 효과가 하강뉴런·운동뉴런까지 도달.
- flybrain의 알려진 한계(우리 설계가 대응해야 하는 것): MBON05는 10~15 Hz로 여유가 없어 어떤 학습률에서도 포화한다. MBON18/21은 어떤 hold에서도 침묵. 가중치는 감소만 하고 바닥은 원래의 20%. 폐루프 결정 실험(verge_swarm)은 55생 뒤 총 가중치 변화 0.5%, 학습 개체와 순진 개체 차이 없음. **입증된 것은 냄새 조건화뿐이며 폐루프 정책 개선은 아직 아무도 보이지 못했다.** 이것이 이 프로젝트의 1번 위험이다.
- Pokémon Showdown 본체(npm `pokemon-showdown` 0.11.11, MIT)는 1세대 모드와 시드 고정 1대1 배틀을 Node 안에서 헤드리스로 돌린다(스모크 테스트 완료). `@pkmn/sim`은 과거 세대 모드를 빼고 배포하므로 쓰지 않는다.

## 2. 아키텍처

```
+-------------------+        JSON lines (stdio)        +--------------------------+
| flymon/battle     | <------------------------------> | Node: pokemon-showdown   |
|  client.py        |   start/choice/state/outcome     |  battle/server.js        |
+---------+---------+                                  +--------------------------+
          |
          v
+-------------------+      candidate odours (4)      +--------------------------+
| flymon/agent.py   | -----------------------------> | flymon/brain             |
|  turn loop        | <----------------------------- |  engine_mps.py (swarm)   |
|  reinforcement    |      MBON valences (4)         |  plasticity / readout    |
+---------+---------+                                +--------------------------+
          |
          v
   logs (JSONL) + checkpoints  --->  analyze.py  --->  results/  --->  web/ viewer
```

한 턴의 순서:
1. 배틀 서버가 `|request|`를 보낸다. 클라이언트가 내 기술 4개, 내·상대 종족과 타입, HP를 상태 객체로 만든다.
2. 인코더가 후보 기술 4개를 냄새 4개로 바꾼다.
3. 스웜의 슬롯 4개(= 초파리 한 마리)에 동시에 제시한다. 4개 슬롯은 가중치를 공유하고 같은 잡음을 받는다(짝지은 설계). 안정화 후 읽기 구간 동안 판독 MBON 발화를 센다.
4. 가치 V = z(접근 집합) − z(회피 집합). 소프트맥스(온도 τ)로 기술을 고른다. 평가 모드는 argmax, 가소성 끔.
5. `>p1 move N`을 보낸다. 서버가 턴을 처리하고 프로토콜 태그(굉장/별로/무효, HP 변화, 기절, 승패)를 돌려준다.
6. 강화: 슬롯 0에 선택한 냄새를 다시 제시하며 도파민 뉴런을 70 mV로 구동한다. 다른 슬롯은 조용히 둔다. 가소성 규칙이 KC→MBON 가중치를 갱신한다.
7. 로그를 쓰고, 배틀이 끝나면 체크포인트를 저장한다.

## 3. 구성 요소

### 3.1 뇌 엔진 (`flymon/brain/`) — 자체 구현, MIT

- **데이터 빌드** `data_build.py`: Janelia MaleCNS v1.0의 세 feather 파일(가중치 1.1 GB, 주석 13 MB, 신경전달물질 42 MB, CC-BY 4.0, neuPrint 로그인 필요)에서 우리 포맷 npz를 만든다. 뉴런 배열: bodyId, type, class, superclass, nt, sign(+1 흥분, −1 억제, 0 도파민 등 조절성), side. 엣지: pre, post, w(시냅스 수). 글루탐산은 억제(GluCl-α), 히스타민 억제. lLN1/lLN2 억제 재지정은 설정 파일에 명시한다. 반구 불균형은 후시냅스 가중치 스케일링으로 보정한다(우측 9.7% 과다 추적). 미러링은 v1 범위 밖.
- **CPU 엔진** `engine_cpu.py`: Shiu et al. 2024 상수(휴지 −52 mV, 역치 −45, τm 20 ms, τsyn 5 ms, 지연 1.8 ms, 불응 2.2 ms, 시냅스당 0.275 mV), α-시냅스, dt 1.0 ms, 이벤트 구동 전파. 수용체는 명령 발화율의 포아송 소스. APL 출력 스케일, MBON 기저 구동, 케니언세포 역치 정규화를 파라미터로 둔다. 검증용 기준 구현이다.
- **MPS 배치 엔진** `engine_mps.py`: 같은 모델을 B개 슬롯에 대해 PyTorch로 돌린다. 커넥톰 행렬은 공유, 상태 [B, N]과 가소성 가중치 [B, E]만 슬롯별. **짝지은 잡음**: 잡음과 수용체 포아송 난수를 [B/4, ·]로 뽑아 4배 반복해서 한 마리의 슬롯 4개가 같은 난수를 받게 한다. hive: 4슬롯 그룹이 가중치를 공유하고 각 슬롯의 갱신 계수를 곱해 적용한다.
- **회로 정의** `circuits.py`: 인구(olfactory, ALPN, Kenyon_Cell, MBON, DAN(PAM/PPL1), APL, DN, 운동뉴런) 인덱스. 도파민 구획 = DAN 타입별 DAN→MBON 직접 시냅스 수를 타입 최대로 정규화, 0.2 이상만 핵심. 이 표를 JSON으로 내보내 README에 싣는다.
- **가소성** `plasticity.py`: 3인자 규칙. KC 자취(τ_kc) × MBON 위상성 도파민(τ_da, 기저 차감) → `w *= 1 − lr·tanh(coincide)`, 바닥 min_weight_frac 0.2. **추가(우리 선택, 라벨링)**: 느린 회복 `w += (w0 − w)·(dt/τ_rec)`로 바닥 누적을 막는다. τ_rec는 M2에서 "100배틀 동안 가소성 가중치 중앙값 ≥ 0.5"(성공 기준 5와 동일)가 되도록 정한다. 도파민 예산(배틀당 상한)은 선택 사항.
- **판독** `readout.py`: 접근 집합 A와 회피 집합 P는 M2에서 측정으로 고른다. 후보: PPL1 계열 어느 타입의 핵심 표적이면서 냄새에 반응하는 MBON(A), PAM 계열 핵심 표적이면서 반응하는 MBON(P). 각 집합의 발화 수를 순진 뇌 기준 평균·표준편차로 z-정규화한 뒤 V = z_A − z_P. 기준 평균·표준편차는 M2에서 순진 뇌에 평가용 매치업 20개의 후보 냄새를 모두 제시해 구하고 설정 파일에 고정한다. 후보 간 d′는 짝지은 잡음 반복(8회)에서 두 후보 V 차이의 평균을 그 표준편차로 나눈 값이다.

### 3.2 배틀 (`flymon/battle/`)

- **서버** `server.js`(Node 24, `pokemon-showdown@0.11.11` 고정): stdin으로 명령, stdout으로 이벤트를 JSON 한 줄씩. 명령: `start{battle_id, seed[4], p1_team, p2_team}`, `choose{battle_id, side, move_index}`, `dex{species|move}`. 이벤트: `request{battle_id, side, moves[], my_hp, my_max}`, `turn_result{battle_id, events[]}`(내 기술의 효과 태그, 급소, 빗나감, HP 변화, 기절), `end{battle_id, winner}`. 여러 배틀을 동시에 연다(배틀당 BattleStream 하나). 포맷 `gen1customgame`, 레벨 100, 1마리씩.
- **클라이언트** `client.py`: 서브프로세스 관리, 배틀 ID별 대기 요청 수집, 배치 단위로 선택을 돌려주는 배리어. 종족·기술 데이터는 `dex` 명령으로 서버에서 받아 캐시한다(정적 추출 파일 없음, 패키지 버전 고정으로 재현).
- **로스터** `roster.py` + `validate_roster.py`: 12마리, 각 4개 공격기. 제약을 코드로 검사한다.
  - 한 마리의 기술 4개는 타입이 서로 다르다(같은 상태에서 후보 냄새 충돌 방지).
  - 종족 속도 ≤ 90 (일반 급소율 ≤ 17.6%).
  - critRatio 1, 명중 100, 부가효과 없음(secondary null), 2턴·반동·재충전 기술 제외, 얼음 기술(1세대 빙결은 영구) 제외.
  - gen1ou TeamValidator로 습득 가능 여부 확인.
  - 로스터 전체에서 타입 종류가 10개 이하(채널 예산).
- **상대 정책** `policies.py`: 무작위, 최대기대데미지(상성×자속×위력, Dex 데이터로 계산). 모두 시드 고정.

### 3.3 인코더 (`flymon/brain/odors.py`)

- 채널 = 후각 수용체 타입. DA1(cVA, 204개 수용체)과 V(CO2)는 제외하고 51개 중 최대 33개 사용: 내 타입(≤10), 상대 타입(≤10), 기술 타입(≤10), 위력 구간 3(<60, 60~89, ≥90). **HP 채널은 v1에서 뺀다**(교체·상태이상 없는 1대1에서 결정과 무관).
- 후보 냄새 = {내 타입1(,2), 상대 타입1(,2), 기술 타입, 위력 구간} → 사구체 4~7개.
- 드라이브 균등화: 채널 강도 ∝ 1/수용체 수, 제시 강도 0.35. PN 발화율로 채널 간 편차 ±20% 이내를 확인한다.
- 같은 턴의 후보 4개는 기술 타입과 위력 구간 채널만 다르다. 이 차이가 케니언세포 결합 코드에서 분리되는지, 그리고 MBON 수준에서 분리되는지를 M2에서 측정한다(주장이 아니라 측정).

### 3.4 강화 신호

받은 데미지는 내 선택과 무관하므로 쓰지 않는다. 신호는 내 기술의 결과에서만 나온다.

| 결과(프로토콜 태그) | 채널 | 펄스 |
|---|---|---|
| 준 데미지 비율 d (0~1) | PAM08 | 400·d ms (급소·난수 포함) |
| `-resisted` | PPL105 | 200 ms |
| `-immune` | PPL105 | 400 ms |
| 상대 기절(승리) | PAM08 | +200 ms |
| 내 기절(패배) | PPL105 | 200 ms (종료 시 1회) |
| 빗나감(1/256) | 없음 | 무신호 |

강화 프로토콜은 flybrain의 조건화 train_block 형태를 따른다: 선택한 냄새를 슬롯 0에 제시하고, 안정화 뒤 펄스 구간 동안 DAN을 70 mV로 구동, 다른 슬롯은 무자극. 한 턴의 뇌 시간 = 안정화 + 읽기 + 안정화 + 펄스.

### 3.5 결정 규칙과 탐색

- 학습 중: softmax(V/τ). τ는 배틀 인덱스의 함수로 1.0 → 0.2 선형 감소(처음 40배틀). 학습 상태 없음.
- 평가: argmax, 가소성 끔.

### 3.6 학습 루프, 체크포인트, 로그 (`agent.py`, `train.py`, `checkpoint.py`)

- 코호트 단위로 돈다: F마리 × 4슬롯 = B. 각 마리는 자기 배틀 일정(내 포켓몬, 상대 포켓몬, 시드)을 미리 받는다. 일정 파일은 대조군과 공유한다.
- 체크포인트: 배틀 경계마다 가중치 [F, E](fp16), 회복 상태, 엔진 RNG, 일정 커서, 설정 해시를 임시 파일에 쓰고 rename. 재개 시 완료 배틀은 건너뛴다. 손상 검출 시 직전 체크포인트로 돌아간다.
- 로그(JSONL): 턴마다 후보 4개의 V, 선택, 효과 태그, HP 변화, 펄스, 판독 집합 발화 수, 케니언세포 활성 수. 배틀마다 구획별 가중치 비율. **스파이크 래스터(KC/MBON/DAN, 1 ms)는 시연 플래그가 켜진 배틀에서만** 저장한다.

### 3.7 리플레이 뷰어 (`web/`)와 문서

- 정적 페이지(GitHub Pages). 입력은 요약 JSONL과 시연 배틀의 래스터. 배틀 로그, 후보 4개 가치 막대, 버섯체 래스터, 구획별 가중치 변화, 코호트 학습 곡선. 스프라이트·공식 에셋 없음. 이름과 타입 색만 사용.
- 영상: 로컬 Showdown 서버 + 공식 웹 클라이언트 화면과 뇌 패널을 나란히 녹화. 저장소에는 배포하지 않는다.
- README(한/영): 측정값과 우리 선택의 구분, 정직한 한계, 선행 연구(flybrain의 verge 증거 포함), 데이터·코드 출처와 CC-BY 표기, 포켓몬 상표 고지(이름·타입만 사용).

## 4. 실험 설계

### 4.1 코호트와 대조군

| 코호트 | 상대 | 마리 | 배틀 | 가소성 | 비고 |
|---|---|---|---|---|---|
| R | 무작위 | 16 | 100 | 켬 | 주 실험 |
| G | 최대데미지 | 16 | 100 | 켬 | 독립 초기화, 순서 혼입 없음 |
| C-off | R과 동일 일정 | 8 | 100 | 끔 | 기준선 |
| C-PAM | 동일 | 8 | 100 | PAM08 무구동 | 보상 채널 |
| C-PPL | 동일 | 8 | 100 | PPL105 무구동 | 처벌 채널 |
| C-shuf | 동일 | 8 | 100 | 켬, KC→MBON 엣지 셔플 | 배선 특이성 |
| REV | R 학습 후 | 16 | 30 | 보상↔처벌 부호 반전 | 반전 시험 |

마리 수와 배틀 수는 M0b 처리량 측정 뒤 예산표로 확정한다. 표의 값은 목표치다.

### 4.2 고정 정책 평가

20배틀마다 가소성·탐색을 끄고 학습에 쓰지 않은 매치업 20개(고정 시드)에서 평가한다.
- **상성 일치율**: 선택한 기술의 효과 배율이 그 상황에서 가능한 최대 배율과 같은 턴의 비율.
- **타입 조건부 선택**: 같은 내 포켓몬에 대해 상대 타입에 따라 선택 기술 타입이 달라지는 정도(상호정보량).
- 승률(보조 지표).

### 4.3 사전 등록 성공 기준

1. 100배틀 시점에서 코호트 R의 상성 일치율이 C-off보다 0.15 이상 높고, 마리 단위 부트스트랩 95% 신뢰구간이 0을 포함하지 않는다.
2. C-PAM과 C-PPL은 각각 R보다 낮고, C-shuf는 C-off와 다르지 않다(배선 특이성).
3. REV 30배틀 뒤 학습된 매치업의 ΔV 부호가 반전한다(마리 단위 부호 검정).
4. 학습 전후 비가소성 가중치 전체가 비트 동일하다(mutation test). 결정 규칙에 학습 상태가 없다(테스트).
5. 100배틀 동안 가소성 가중치 중앙값 ≥ 0.5(바닥 누적 없음).

기준 1을 못 넘으면 "학습 안 됨"으로 보고한다. 결과를 바꾸기 위해 기준을 사후에 조정하지 않는다.

## 5. 마일스톤과 게이트

- **M0 엔진과 재현**: 스캐폴드(uv, Python 3.13, Node 24, pytest). 데이터 빌드. CPU 엔진. flybrain 측정값 재현: 설계된 8사구체 냄새 쌍에서 KC 활성 5%±2, Jaccard ≤ 우연 수준; MBON 기저 3~4 Hz; **조건화 반전 8/8 시드**. 이 마지막 항목이 엔진 합격 기준이다. 병행: flybrain 저자에게 라이선스 이슈(참조·감사 표기 목적).
- **M0b MPS 스웜**: 배치 엔진, 짝지은 잡음, hive. CPU 대비 통계적 일치(KC/MBON/DN 스파이크 수). 처리량 측정(B=32, 64, 128에서 ms/step, 가소성 켬). 전체 실험 행렬의 시간·메모리·로그 용량 외삽 → 예산표를 이 문서 부록에 기록. 부족하면 마리 수·배틀 수를 줄인다. 축소 회로는 이 단계에서 만들지 않는다.
- **M1 배틀**: server.js, client.py, 로스터와 검증 스크립트, 상대 정책. 테스트: 시드 재현성, 요청 파싱, 효과 태그 추출, 후보 냄새 유일성.
- **M2 인코더·판독·학습 단위 시험(go/no-go)**: 채널 균등화, 후보 KC 활성 5~9%, 같은 턴 후보의 MBON 수준 분리, 공통 채널만 바꿨을 때 순위 보존율, 판독 집합 선정, 창 길이 수렴 측정으로 고정. **학습 단위 시험**: 순진 뇌에서 상위 두 후보의 d′ ≈ 0, 한 후보에 보상 20회 뒤 그 후보의 V가 오르고 d′ ≥ 1, 처벌 20회 뒤 내려감. 실패하면 여기서 멈추고 보고한다.
- **M3 에이전트 루프**: 턴 루프, 강화, 체크포인트·재개, 로그 스키마, 작은 배치 스모크.
- **M4 실험**: 4.1 행렬, 고정 정책 평가, 분석 스크립트, 결과 JSON과 그림.
- **M5 공개물**: 뷰어, README 한/영, 영상.
- **v2 백로그**: 로컬 Showdown 서버에 봇 계정으로 붙는 사람 대전, `gen11v1`(3마리 중 1마리 선택), 교체 있는 6대6, 브라우저 축소 버섯체 시연.

## 8. 테스트 전략

- 단위: 엔진 상수·적분(작은 회로에서 해석해 비교), 구획 표 생성, 인코더 유일성·균등화, 서버 프로토콜 파싱, 로스터 제약, 체크포인트 왕복.
- 통계: CPU 대 MPS 스파이크 수 일치, 재현 측정(M0)의 수치 범위.
- 불변식: 비가소성 가중치 비트 동일, 결정 규칙 무상태, 같은 시드·같은 일정에서 로그 동일.
- 통합: F=2, 배틀 2, 창 길이 축소로 전체 루프 스모크.

## 9. 미결 사항

- Janelia 데이터 다운로드는 사용자가 neuPrint 계정으로 수행한다. 파일 해시를 문서에 기록한다.
- 판독 집합, 창 길이, τ_rec, 펄스 길이의 최종값은 M2 측정 뒤 이 문서에 부록으로 추가한다.
