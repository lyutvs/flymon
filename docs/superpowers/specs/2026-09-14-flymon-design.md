# FlyMon 설계 문서 — 초파리 뇌(MaleCNS) + 코치가 1세대 OU 6대6 포켓몬 배틀을 한다

- 작성일: 2026-09-14
- 상태: 초안 v3 (v2에서 범위를 1대1 → 6대6 하이브리드로 확장. 레드팀 18건, Showdown 룰북, 선행 프로젝트 조사 반영)
- 작업 브랜치: `open-fly-brain-connectome`

## 0. 목표와 정확한 주장

**게임**: Pokémon Showdown 1세대 OU 6대6 전부. 교체, 상태이상, 랭크 변화, 잠듦·마비, 부분 구속까지 Showdown 엔진 규칙 그대로.

**역할 분담(하이브리드)**:
- **초파리 뇌**: MaleCNS v1.0 커넥톰(약 16만 뉴런) 전체 LIF 스파이킹 모델. 매 턴 "공격기 중 무엇을 쓸까"를 결정한다. 학습은 뇌 안의 실제 KC→MBON 시냅스(33,496개)에서 도파민 게이트 억제로만 일어난다.
- **코치**: 외부 정책. 교체할지, 상태기·보조기를 쓸지, 기절 뒤 누굴 낼지를 결정한다. v1은 poke-env의 SimpleHeuristicsPlayer 규칙(상성·속도·HP·랭크 기반, 교체 판단 포함). v2 후보는 Metamon 사전학습 에이전트.
- **결정 라우터**: 코치가 "공격"을 택했고 쓸 수 있는 공격기가 2개 이상이면 초파리가 고른다. 그 외는 코치가 고른다. 매 턴 누가 결정했는지 기록·표시한다.

**주장할 수 있는 것**: 실제 6대6 배틀 안에서 초파리 뇌가 공격기 선택을 상성에 맞게 학습한다. 초파리의 기여는 "초파리를 끄고 공격기를 무작위로 고른 코치"와의 승률·선택 일치율 차이로 측정한다.

**정확히 구분해서 적을 것**:
- 학습되는 파라미터는 KC→MBON 가중치뿐. 초파리의 선택 규칙(MBON 가치 → softmax/argmax)에는 학습 상태가 없다.
- 코치는 학습하지 않는다(v1 규칙 기반). 코치가 배틀의 전략을 맡으므로 승률의 상당 부분은 코치 몫이다. 그래서 기여도는 반드시 절제(ablation)로 보인다.
- 관측 인코딩, 판독 집합, 도파민 펄스, 가중치 회복은 우리 설계 선택. 커넥톰이 주는 것은 연결·시냅스 수·신경전달물질 예측.
- 후각엽+버섯체 축소 회로는 탐색 실험 전용. 최종 결과는 전체 뇌 실행으로만 인정.
- 초파리는 한 단계 가치 판단만 한다. 계획이나 턴 간 신용 배분은 없고, 그 몫은 코치다.

## 1. 사전 조사 요약과 근거

- 커넥톰 LIF에 도파민 가소성을 붙였을 때 냄새 특이적 학습이 나오지 않는 것을 두 프로젝트(fly-brain-bench, flybrain)가 기록했다. flybrain(MaleCNS, 단일 커밋, 라이선스 없음)은 원인을 고쳤고 수치를 FINDINGS.md에 남겼다. 우리는 그 설계 결정과 측정값을 **재현 목표**로 삼고 코드는 복사하지 않는다.
  - 후각엽 국소뉴런 lLN1/lLN2 억제성 재지정(151세포). APL 출력 스케일 0.1, kc_thresh 1.0~1.5 → 케니언세포 5% 활성, 설계된 두 냄새의 겹침 0.
  - MBON 기저 구동 0.85 → 기저 3.4 Hz. 도파민 구획은 DAN 타입별 DAN→MBON 직접 시냅스, 핵심 = 타입 최대의 0.2 이상. PPL105 → MBON13/18/23, PAM08 → MBON05/21, 겹침 없음.
  - 학습률 0.0003, DAN 70 mV, 냄새 강도 0.35(PN ~130 Hz), 800 ms. 8/8 시드 반전, 두 구획 독립 가산. 학습 효과가 하강·운동뉴런까지 도달.
  - 알려진 한계: MBON05 포화, MBON18/21 침묵, 감소 전용 규칙과 바닥 20%. 폐루프 결정(verge_swarm)은 55생 뒤 가중치 변화 0.5%, 학습 개체와 순진 개체 차이 없음. **폐루프 정책 개선은 아직 아무도 보이지 못했다.** 1번 위험.
- 선행 게임 프로젝트는 네 부류다. 고정 매핑(마리오64, FightingICE), 뇌 고정 + 외부 readout 학습(비트세이버, Dino, craftax), 뇌 안 가소성 시도(doomfly 실패, FlyPong 부정 결과, flybrain 성공), 부분 회로. 우리는 세 번째 부류에 코치를 얹은 형태다. 신뢰받는 프로젝트의 공통점은 "측정된 것 / 우리가 정한 것 / 안 된 것"을 장부처럼 분리하는 것이며 우리도 따른다.
- Pokémon Showdown 본체(npm `pokemon-showdown` 0.11.11, MIT)는 1세대 모드와 시드 고정 배틀을 헤드리스로 돌린다(스모크 완료). 로컬 서버(`node pokemon-showdown start --no-security`)에 공식 웹 클라이언트를 붙이면 UI가 따라온다.
- poke-env 0.16.1(MIT, Python ≥3.10): 로컬 서버에 웹소켓으로 붙는 파이썬 클라이언트. 6대6 상태 파싱(내·상대 팀, HP, 상태, 랭크, 공개된 정보), `available_moves`, `available_switches`, `damage_multiplier`, 동시 배틀, 비동기 `choose_move`. SimpleHeuristicsPlayer가 내장.
- Metamon(MIT): 1세대 OU 사전학습 정책 40개 이상(허깅페이스), 사람 리플레이 530만 궤적, 표준 팀 세트. 실행에는 자체 서버 포크가 필요. 코치 v2 후보.
- 1세대 룰(Showdown gen1 mod 구현): 아이템·특성 없음, "특수" 단일 스탯, 급소율 = 종족 속도/512(고급소 기술은 /64), 모든 기술 1/256 빗나감, 빙결 영구, 잠듦 1~7턴, 고스트→에스퍼 무효, 불→얼음 2배, 벌레↔독 2배.

## 2. 아키텍처

```
+-----------------------------+   websocket   +------------------------------+
| Node: pokemon-showdown 서버 | <-----------> | Python: poke-env             |
|  gen1ou, --no-security      |               |  FlyCoachPlayer (우리)       |
|  (사람은 공식 웹 클라이언트) |               |  상대: Random/MaxBP/Heuristic |
+-----------------------------+               +---------------+--------------+
                                                              |
                          +-----------------------------------+------------------+
                          |  결정 라우터                                          |
                          |  코치 주문 = 공격기 & 공격기 후보 ≥ 2 → 초파리        |
                          |  그 외(교체·상태기·강제 교체·후보 1개) → 코치          |
                          +--------+---------------------------------+----------+
                                   |                                 |
                     후보 냄새(≤4) |                                 | 코치 주문
                                   v                                 v
                   +------------------------------+          (그대로 서버로)
                   | 뇌 스웜 engine_mps.py        |
                   |  슬롯 4개 = 초파리 1마리      |
                   |  판독 → V(후보) → softmax     |
                   |  강화: PAM08 / PPL105        |
                   +------------------------------+
   로그(JSONL) + 체크포인트 → analyze.py → results/ → web/ 뷰어 · 영상
```

한 턴의 순서:
1. poke-env가 배틀 상태를 준다. 코치가 자기 주문(order)을 계산한다.
2. 라우터: 코치 주문이 공격기이고, `available_moves` 중 공격기(위력 > 0, 우리 제약을 만족)가 2개 이상이면 초파리 차례. 아니면 코치 주문을 그대로 보낸다. 결정 주체를 로그에 남긴다.
3. 초파리 차례: 인코더가 공격기 후보(≤4)를 냄새로 만든다. 스웜 슬롯 4개에 동시에 제시(가중치 공유, 같은 잡음). 안정화 뒤 읽기 구간의 판독 MBON 발화로 V를 계산. softmax(V/τ)로 선택. 평가 모드는 argmax, 가소성 끔.
4. 서버가 턴을 처리한다. poke-env 이벤트에서 내 기술의 효과(굉장/별로/무효), 대상 HP 변화, 대상 기절을 읽는다.
5. 강화(초파리가 결정한 턴만): 슬롯 0에 선택한 냄새를 재제시하며 DAN을 70 mV로 구동. 가소성 규칙이 KC→MBON을 갱신.
6. 배틀이 끝나면 체크포인트.

**배치 처리**: 코호트의 F마리는 각자 배틀을 동시에 진행한다(poke-env `max_concurrent_battles`). FlyCoachPlayer의 비동기 `choose_move`는 초파리 차례가 오면 배치 배리어를 기다리고, 배리어는 대기 중인 모든 배틀의 후보를 모아 스웜을 한 번 돌린 뒤 각자에게 결과를 돌려준다. 타임아웃(예: 마리 수의 절반이 대기하면 즉시 실행)으로 교착을 막는다. M1에서 검증한다.

## 3. 구성 요소

### 3.1 뇌 엔진 (`flymon/brain/`) — 자체 구현, MIT

- **데이터 빌드** `data_build.py`: Janelia MaleCNS v1.0 세 feather 파일(가중치 1.1 GB, 주석 13 MB, 신경전달물질 42 MB, CC-BY 4.0, neuPrint 로그인 필요) → 우리 npz. 뉴런: bodyId, type, class, superclass, nt, sign(+1/−1/0), side. 엣지: pre, post, w. 글루탐산·히스타민 억제. lLN1/lLN2 억제 재지정은 설정 파일에 명시. 반구 불균형은 후시냅스 가중치 스케일링으로 보정. 미러링은 v1 범위 밖.
- **CPU 엔진** `engine_cpu.py`: Shiu et al. 2024 상수(휴지 −52 mV, 역치 −45, τm 20 ms, τsyn 5 ms, 지연 1.8 ms, 불응 2.2 ms, 0.275 mV/시냅스), α-시냅스, dt 1 ms, 이벤트 구동. 수용체는 포아송 소스. APL 스케일, MBON 기저 구동, KC 역치 정규화를 파라미터로. 검증 기준 구현.
- **MPS 배치 엔진** `engine_mps.py`: B슬롯 동시. 커넥톰 공유, 상태 [B, N]과 가소성 가중치 [B, E]만 슬롯별. **짝지은 잡음**: 잡음과 포아송 난수를 [B/4, ·]로 뽑아 4배 반복. hive: 4슬롯이 가중치 공유, 갱신 계수를 곱해 적용.
- **회로 정의** `circuits.py`: 인구 인덱스, 도파민 구획 표(JSON 내보내기, README 수록).
- **가소성** `plasticity.py`: 3인자 규칙 `w *= 1 − lr·tanh(KC자취 × 위상성DA)`, 바닥 0.2. **추가(우리 선택, 라벨링)**: 느린 회복 `w += (w0 − w)·dt/τ_rec`. τ_rec는 M2에서 "100배틀 동안 가소성 가중치 중앙값 ≥ 0.5"(성공 기준 5)가 되도록 정한다.
- **판독** `readout.py`: 접근 집합 A(PPL1 계열 핵심 표적이며 반응하는 MBON), 회피 집합 P(PAM 계열 핵심 표적이며 반응하는 MBON)를 M2에서 측정으로 고른다. V = z_A − z_P. 기준 평균·표준편차는 순진 뇌에 평가용 상황의 후보 냄새를 제시해 구하고 설정 파일에 고정. 후보 간 d′는 짝지은 잡음 반복(8회)에서 V 차이의 평균/표준편차.

### 3.2 배틀 환경 (`flymon/battle/`)

- **서버**: `pokemon-showdown@0.11.11` 고정, 로컬 `--no-security`. 포맷 `gen1ou`. 사람 대전은 같은 서버에 공식 웹 클라이언트로 접속.
- **플레이어** `fly_coach_player.py`: poke-env `Player` 서브클래스. 코치·라우터·초파리 호출·강화·로그. 상대 플레이어: `RandomPlayer`, `MaxBasePowerPlayer`, `SimpleHeuristicsPlayer`(코치 단독 미러). 배틀 일정(내 팀, 상대 팀, 상대 정책 시드)은 파일로 미리 생성해 대조군과 공유한다. 서버 난수는 고정할 수 없으므로 짝짓기는 일정 수준에서 한다.
- **코치** `coach.py`: v1 = SimpleHeuristicsPlayer의 규칙을 함수로 감싼 것(교체 판단 `_should_switch_out`, 상성 점수, 랭크업 조건). 코치가 낸 주문이 공격기인지 판정하는 인터페이스를 노출. v2 = Metamon 정책(별도 서버 포크 필요, 백로그).
- **팀 풀** `teams.py` + `validate_pool.py`: 1세대 OU 합법 포켓몬 16마리. 각 마리는 공격기 2~3개 + 보조기 1~2개. 배틀마다 양쪽이 풀에서 6마리를 시드로 뽑는다.
  - **초파리 후보가 되는 공격기 제약**(코드로 검사): 같은 마리 안에서 타입 상이, critRatio 1, 2턴·반동·재충전 아님, 빙결 유발 아님, 부가효과 없거나 경미. 종족 속도 ≤ 100(급소율 ≤ 19.5%).
  - 보조기(코치 전용): 전기파, 리플렉터, 회복, 명상/칼춤 등. 잠듦기는 v1 제외(Sleep Clause와 1~7턴 잡음).
  - 표준 OU 세트(바디슬램 마비 30%, 눈보라 빙결, 파괴광선)는 제외. README에 "메타와 다른 제한 풀"임을 적는다.
  - gen1ou TeamValidator로 합법성 확인.
- **후보 추출**: `available_moves` 중 위력 > 0인 기술 전부. 풀의 공격기는 모두 위 제약을 만족하도록 검증되므로 "쓸 수 있는 공격기 = 초파리 후보"가 성립하고, 코치가 고른 공격기는 항상 후보 안에 있다. 4개를 넘지 않는다(팀 풀 제약).

### 3.3 인코더 (`flymon/brain/odors.py`)

- 채널 = 후각 수용체 타입. DA1(cVA)과 V(CO2) 제외, 51개 중 최대 45개: 내 타입(≤12), 상대 타입(≤12), 기술 타입(≤12), 위력 구간 3(<60, 60~89, ≥90), 내 HP 구간 3, 상대 HP 구간 3. 6대6에서는 교체와 마무리가 있으므로 HP 채널을 쓴다(v2 설계에서 뺐던 것을 복귀).
- 후보 냄새 = {내 타입1(,2), 상대 타입1(,2), 기술 타입, 위력 구간, 내 HP, 상대 HP} → 사구체 6~9개.
- 드라이브 균등화: 채널 강도 ∝ 1/수용체 수, 제시 강도 0.35. PN 발화율 편차 ±20% 이내 확인.
- 같은 턴 후보는 기술 타입·위력 채널만 다르다. KC 결합 코드와 MBON 수준 분리를 M2에서 측정한다.

### 3.4 강화 신호 (초파리가 결정한 턴만)

받은 데미지와 배틀 승패는 내 공격기 선택과 무관하므로 쓰지 않는다.

| 결과 | 채널 | 펄스 |
|---|---|---|
| 대상 최대 HP 대비 준 데미지 비율 d | PAM08 | 400·d ms |
| `-resisted` | PPL105 | 200 ms |
| `-immune` | PPL105 | 400 ms |
| 대상 기절 | PAM08 | +200 ms |
| 빗나감·풀마비·행동 불가 | 없음 | 무신호 |

프로토콜: 선택한 냄새를 슬롯 0에 제시, 안정화 뒤 펄스 구간 동안 DAN 70 mV, 다른 슬롯 무자극.

### 3.5 결정 규칙과 탐색

- 학습 중 softmax(V/τ), τ는 배틀 인덱스 함수로 1.0 → 0.2 선형(첫 40배틀). 학습 상태 없음.
- 평가: argmax, 가소성 끔.

### 3.6 학습 루프, 체크포인트, 로그

- 코호트: F마리 × 4슬롯 = B. 각 마리는 poke-env 플레이어 인스턴스 하나에 대응하고 자기 배틀 일정을 받는다.
- 체크포인트: 배틀 경계마다 가중치 [F, E](fp16), 회복 상태, 엔진 RNG, 일정 커서, 설정 해시를 임시 파일에 쓰고 rename. 재개 시 완료 배틀 건너뜀. 손상 검출 시 직전 체크포인트.
- 로그(JSONL): 턴마다 결정 주체, 코치 주문, 후보 V, 선택, 효과 태그, HP 변화, 펄스, 판독 발화 수, KC 활성 수. 배틀마다 구획별 가중치 비율, 승패, 초파리 결정 턴 수. 스파이크 래스터는 시연 플래그 배틀만.

### 3.7 공개물

- **뷰어**(`web/`, 정적, GitHub Pages): 배틀 로그에 턴별 "초파리/코치" 표시, 후보 4개 가치 막대, 버섯체 래스터(시연 배틀), 구획별 가중치 변화, 코호트 학습 곡선과 절제 비교. 스프라이트 없음.
- **영상**: 로컬 서버의 공식 웹 클라이언트 화면 + 뇌 패널 + 결정 주체 배지를 나란히 녹화. 저장소에 에셋 배포 없음.
- **README(한/영)**: 측정값/우리 선택/안 된 것 구분, 초파리·코치 역할 표, 절제 결과, 한계(제한 팀 풀, 한 단계 가치 판단), 데이터·코드 출처와 CC-BY, 포켓몬 상표 고지.

## 4. 실험 설계

### 4.1 코호트, 대조군, 절제

| 팔 | 공격기 결정 | 코치 | 상대 | 마리 | 배틀 | 가소성 |
|---|---|---|---|---|---|---|
| FLY | 초파리 | v1 | SimpleHeuristics | 16 | 100 | 켬 |
| FLY-R | 초파리 | v1 | Random | 16 | 100 | 켬 |
| RND | 무작위 공격기 | v1 | SimpleHeuristics | 8 | 100 | — |
| MAX | 최대 기대 데미지 | v1 | SimpleHeuristics | 8 | 100 | — (상한) |
| C-off | 초파리 | v1 | SimpleHeuristics | 8 | 100 | 끔 |
| C-PAM | 초파리 | v1 | SimpleHeuristics | 8 | 100 | PAM08 무구동 |
| C-PPL | 초파리 | v1 | SimpleHeuristics | 8 | 100 | PPL105 무구동 |
| C-shuf | 초파리 | v1 | SimpleHeuristics | 8 | 100 | 켬, KC→MBON 셔플 |
| REV | FLY 학습 후 | v1 | SimpleHeuristics | 16 | 30 | 보상↔처벌 반전 |

모든 팔은 같은 배틀 일정 파일을 쓴다. 마리·배틀 수는 M0b 예산표로 확정한다(6대6은 배틀당 초파리 결정이 10~25회로 1대1의 2~3배).

### 4.2 고정 정책 평가

20배틀마다 가소성·탐색을 끄고 평가용 일정 20배틀(학습에 없는 팀 조합)에서:
- **상성 일치율**: 초파리가 결정한 턴 중 선택한 기술의 효과 배율이 후보 최대 배율과 같은 비율.
- **MAX 일치율**: 최대 기대 데미지 기술과 같은 선택의 비율.
- **타입 조건부 선택**: 같은 내 포켓몬에서 상대 타입에 따라 선택 기술 타입이 달라지는 정도(상호정보량).
- **승률**(코치 영향 포함, 보조 지표).

### 4.3 사전 등록 성공 기준

1. 100배틀 시점 FLY의 상성 일치율이 C-off보다 0.15 이상 높고, 마리 단위 부트스트랩 95% CI가 0을 제외.
2. **기여도**: FLY 승률 > RND 승률, 마리 단위 CI가 0을 제외. MAX는 상한으로 보고.
3. C-PAM·C-PPL은 FLY보다 낮고, C-shuf는 C-off와 다르지 않다.
4. REV 30배틀 뒤 학습된 상황의 ΔV 부호 반전(마리 단위 부호 검정).
5. 비가소성 가중치 비트 동일(mutation test), 결정 규칙 무상태(테스트), 100배틀 동안 가소성 가중치 중앙값 ≥ 0.5.

기준 1 또는 2를 못 넘으면 그대로 보고한다. 사후 조정 없음.

## 5. 마일스톤과 게이트

- **M0 엔진과 재현**: 스캐폴드(uv, Python 3.13, Node 24, pytest). 데이터 빌드. CPU 엔진. flybrain 측정값 재현: KC 활성 5%±2, Jaccard ≤ 우연, MBON 기저 3~4 Hz, **조건화 반전 8/8 시드**(엔진 합격 기준). 병행: flybrain 저자에게 감사·라이선스 이슈.
- **M0b MPS 스웜**: 배치 엔진, 짝지은 잡음, hive. CPU 대비 통계적 일치. 처리량(B=32/64/128, 가소성 켬). 전체 실험 행렬 외삽 → 예산표를 부록에 기록. 축소 회로는 만들지 않는다.
- **M1 배틀 환경**: 로컬 서버 설치 스크립트, FlyCoachPlayer(코치·라우터·배치 배리어), 팀 풀과 검증, 상대 플레이어, 일정 생성기. 테스트: 라우터 판정(공격/비공격/후보 1개/강제 교체), 후보 추출과 냄새 유일성, 동시 배틀 배리어 교착 없음, 일정 재현성, 효과 태그 추출. 초파리 자리에 무작위를 넣고 100배틀 스모크(RND 팔의 조기 실행).
- **M2 인코더·판독·학습 단위 시험(go/no-go)**: 채널 균등화, 후보 KC 활성 5~9%, 같은 턴 후보의 MBON 분리, 공통 채널만 바꿨을 때 순위 보존율, 판독 집합 선정, 창 길이를 수렴 측정으로 고정. **학습 단위 시험**: 순진 뇌 d′ ≈ 0, 보상 20회 뒤 d′ ≥ 1, 처벌 20회 뒤 하락. 실패하면 멈추고 보고.
- **M3 에이전트 루프**: 초파리 결정·강화를 FlyCoachPlayer에 연결, 체크포인트·재개, 로그 스키마, F=2 배틀 2 스모크.
- **M4 실험**: 4.1 행렬, 고정 정책 평가, 분석, 결과 JSON·그림.
- **M5 공개물**: 뷰어, README, 영상. 사람 대전은 서버가 있으니 봇 계정을 챌린지 대기 상태로 두는 스크립트만 추가(작음).
- **v2 백로그**: 초파리가 교체 대상도 선택, Metamon 코치, 표준 OU 세트 허용, 뇌 특징 + PPO 팔(뇌 vs 셔플 vs 없음 비교), 브라우저 축소 버섯체 시연.

## 8. 테스트 전략

- 단위: 엔진 적분(작은 회로 해석 비교), 구획 표, 인코더 유일성·균등화, 라우터 판정, 후보 추출, 팀 풀 제약, 체크포인트 왕복.

- 불변식: 비가소성 가중치 비트 동일, 결정 규칙 무상태, 같은 일정에서 결정 주체 로그 동일.
- 통합: F=2, 배틀 2, 창 길이 축소로 전체 루프 스모크. 초파리 자리에 무작위를 넣은 100배틀 스모크(M1).
