## 0. 목적과 성공 기준

**목적**: 포켓몬 상황 → 냄새(ORN 입력) 인코더를 다시 설계해, M2 학습 단위 시험의 **오라클 선행조건**이 성립하게 한다. 성립의 기준은 메인 스펙이 이미 쓰는 오라클 기준이다(학습 시험 자체는 이 트랙 밖).

**성공 기준(이 트랙의 `SELECTED`)**: C3 엔진·H.4 판독(MBON13/MBON05)·H.4 오라클 절차에서, 측정하지 않은 사전 고정 판정 세트(L 생성기의 턴 64 이후, 5.1 — 목록은 결과 전에 생성·커밋하고 측정만 맹검)의
(b) 21쌍 중 시험 가능 쌍 n ≥ 11(= T_b ≥ 0.5) ∧ 순진 균형 (a) 쌍의 시험 가능 수 F_a ≥ 2 ∧ n이 같은 세트 E0의 c보다 크다 ∧ c < 11(5.3의 평가 순서 2에 따라 c ≥ 11이면 결론을 내지 않는다).
이것은 **오라클 시험 가능성**이며 학습 시험이 아니다. `SELECTED` 뒤 F v4 학습 시험 선언은 이 트랙 밖이며 사용자가 결정한다.

## 1. 배경 (기록된 데이터)

- 메인 부록 I: M2는 2026-09-22부터 "시험 불성립". E0(메인 3.3) 인코더에서 이상화한 특이 감소(오라클)로도 (b) 상대 타입 축 시험 가능 쌍이 C3 7/21(기준 ≥ 11).
- 메인 G.12·G.13: 인코더 E0–E3(배정·복제·어휘만 바꿈)의 점수 0.14–0.22. 변화량 기준으로 병목은 (b) 축 보상.
- 엔진 지렛대(J STD, K KC→KC 억제, M 판독 확장)와 주장 축소(L, 재범위, N)는 모두 닫혔다. 부록 O(실제 냄새): 처벌 학습이 제시 유발 억압과 갈렸다(`SEPARABLE`).
  N.9: KC Jaccard 0.19인 다른 쌍은 시험 가능, 0.48인 비슷한 쌍은 불가.
- **구조적 원인**: E0의 냄새는 기호마다 사구체 하나(내 타입·상대 타입·기술 타입·위력·내 HP·상대 HP)로 약 8–9 사구체다. (b) 쌍은 상대 타입 채널만 다르므로 X·Y가
  **사구체 8–9개 중 6–7개를 공유**하고, (a) 쌍도 기술·위력 채널만 다르다. 배정·복제·어휘를 바꾼 E1–E3는 이 공유 구조를 그대로 두었다.

## 2. 결정 기록 (사용자, 2026-10-01)

1. **부호 단위 = 결합 부호**: (기술 타입 × 상대 타입) 조합마다 고유한 사구체 패턴. 인수별 채널(내 타입·HP·위력)은 쓰지 않는다.
2. **선택·판정 = 짝수 선택 → L 세트 판정**: 설정 ≤ 4개 격자에서 짝수 턴 오라클로 고르고, L 생성기의 미사용 구간에서 만든 판정 세트(5.1, 레드팀 뒤 D1)에서 M2 기준으로 한 번만 판정한다.
3. **접근 = A 격자 서로소**: 축 쌍의 사구체 겹침을 구조로 0으로 만들고 단위 테스트로 검증한다. P 트랙의 실제 냄새 데이터와 겹치지 않는다.
4. 강도 s는 오라클이 아니라 KC 활성만으로 고정한다. 대역에 못 닿는 설정은 자격 없음.
5. 하드 제약 위반 0에 못 닿는 설정은 자격 없음(소프트 완화로 살리지 않는다). 알파벳이 k마다 다른 것은 선택 단계라 허용.
6. 격자·선택 규칙·동률 규칙·L 판정 기준은 짝수 턴을 돌리기 전에 이 문서에 고정·커밋한다.
7. 짝수 최고 T_b < 0.5 또는 자격 설정 없음 → 판정 세트를 쓰지 않고 멈춘다(D3로 "짝수 통과 설정 없음"으로 정밀화).
8. 보정·구동 측정 시드 블록은 오라클 시드·판정 시드와 겹치지 않음을 명시하고 단위 테스트로 확인한다.
9. 비교 기준 c = 같은 판정 세트의 E0. 판독 구간은 고정된 평가 순서로 매긴다(5.3).

**주장에 생기는 변화(명시)**: 설계상 축 쌍의 입력 사구체 겹침이 0이므로 초파리는 결합(기술 타입 × 상대 타입)별 가치를 배우는 구조다. 결합 간 일반화(소프트 공유 ≤ 1, KC 수준 공유)는 측정하지 않는다. 1차 주장("같은 내 포켓몬·같은 후보 기술에서 상대 타입이 바뀌면 선택을
바꾼다")은 문자 그대로 유지된다. 상대 타입 채널을 뺀 대조군 FLY-TB의 E-grid 정의는 M4의 일이며 이 트랙에서 정하지 않는다. 정의 가능성만 적는다: 상대 타입을 무시하는 부호(예: 기술 타입 행마다 고정 코드워드 하나)로 만들 수 있으며, 결합 부호 자체가 FLY-TB를 막지는 않는다.

## 3. 인코더 E-grid

### 3.1 기호와 알파벳

- 기술 타입 8(ELECTRIC, FIRE, GRASS, GROUND, NORMAL, PSYCHIC, ROCK, WATER) × 상대 타입 12(DRAGON … WATER) = **96 셀**. 어휘는 `h4_pairs.pool_vocabulary()`(16종 풀, 1세대)에서 읽는다.
  풀의 모든 포켓몬은 공격기 타입이 서로 다르므로 같은 턴 후보가 같은 셀을 공유하지 않는다(단위 테스트로 확인).
- 셀마다 **k개 사구체**의 코드워드. 알파벳: 모델 ORN 수용체 타입 51개 중 `ORN_DA1`·`ORN_V`를 뺀 49개에서 고른다(메인 3.3의 제외 규칙).
  - k = 2: 4.1의 C3 단독 구동 측정에서 구동 대역 400–3200 스파이크의 기하평균(≈ 1131)에 log 거리로 가까운 **40개**(동률은 이름순). 모든 log는 log₁₀(x + 1)로 계산한다(구동 0인 사구체도 정의됨).
  - k = 3: **49개 전부**.
- 풀에 나타나는 이중 타입 조합 **10개**(`pool_vocabulary`에서 파생, 예: GRASS/POISON): D.

### 3.2 제약

- **하드**(위반 0이어야 자격): 두 셀 (m₁, t₁), (m₂, t₂)는 다음 중 하나면 사구체가 서로소다 — ① m₁ = m₂(같은 행) ② t₁ = t₂(같은 열) ③ {t₁, t₂} ∈ D(m₁ ≠ m₂).
  ③은 상대가 이중 타입일 때 (a) 쌍의 교차항((m₁, t₁) 대 (m₂, t₂))까지 서로소로 만든다.
- **소프트**(목적함수, 기록): 그 밖의 셀 쌍은 공유 사구체 ≤ 1.
- **결과**: 모든 (a) 쌍(같은 상대, 다른 기술)과 (b) 쌍(같은 기술, 타입이 겹치지 않는 대체 상대)의 사구체 겹침 = **0**. 짝수 턴·판정 세트·실제 배틀 어디서든 같다.

### 3.3 코드북 생성 (결정적, D7)

- **하드 제약 해는 구성적으로 만든다.** 하드 제약 충돌 그래프(셀 96개, 3.2의 ①–③이면 간선)를 DSATUR로 칠한다(동률은 셀 인덱스 순 — 기술 타입 순, 그다음 상대 타입 순).
  색 수 C에서 C·k ≤ |알파벳|이면 색 c의 모든 셀에 알파벳의 k개 슬롯 {c·k, …, c·k + k − 1}(알파벳은 4.1 구동 순)을 주어 하드 위반 0인 시작 코드북을 만든다.
  같은 색 셀끼리는 하드 제약이 없으므로 이 시작 해는 하드 위반 0이다(소프트는 위반할 수 있다). 스크래치(레드팀 sol): C = 16, k = 3이면 48 ≤ 49.
- C·k > |알파벳|이면 정확 탐색(백트래킹, 셀 순서 DSATUR)으로 하드 위반 0인 코드북을 찾는다. 하드 충돌 그래프의 최대 클리크 ω에 대해 ω·k > |알파벳|이면 **불가능 증명**이다.
- **자격 없음은 불가능 증명(`INFEASIBLE`)일 때만**이다. 구성도 정확 탐색도 끝나지 않고 불가능도 증명되지 않으면 `UNDECIDED`로 기록하고 멈춘다(사용자 몫). 하드 제약은 완화하지 않는다(결정 5).
- **최적화**: 시작 해에서 담금질로 J = (소프트 위반 수) + (코드워드 구동 합의 log₁₀(x + 1) 분산)을 줄인다. 이동 = 셀 하나의 사구체 하나를 그 셀에 없는 알파벳 사구체로 바꾸기;
  **하드 위반을 만드는 이동은 거부**한다. 온도 선형 2.0 → 0.03, 반복 200 000회, 재시작 r = 0..7(같은 시작 해, 난수 `numpy.random.default_rng(20261001 + 1000·k + r)`),
  J가 가장 작은 재시작을 채택(동률은 작은 r). 구동은 4.1의 단독 측정값(사구체별 KC 스파이크 수의 시드 평균). 실행 시간은 스모크에서 재서 11절에 적는다.
- 채택 코드북은 JSON으로 커밋하고 digest로 고정한다(`results/summary/encoder_grid.json`에 기록). 테스트는 커밋본의 하드 제약을 전수 검사한다.
- 생성 단계 스크래치 측정(2026-10-01, 기록 — 판정 아님): 무작위 시작 담금질은 k = 2·N = 40 하드·소프트 위반 0, k = 3·N = 49 하드 위반 2였다 — 그래서 구성적 시작으로 바꿨다.

### 3.4 상황 냄새

- `odour(m, 상대 타입들)` = 상대의 각 타입 t에 대한 셀 (m, t) 코드워드의 합집합 — 단일 타입 k개, 이중 타입 2k개 사구체(하드 ①로 서로소).
- 냄새 안 강도 sᵍ ∝ 1/(그 사구체의 수용체 수), 평균 1(E0 규약, `h4_pairs.odour`와 같은 식). 제시는 `stimuli.present(engine, pops, odor, strength)`.
- **이중 타입 규칙**(격자 축):
  - `full`: 위 그대로(이중 타입은 총 구동이 단일의 약 2배).
  - `norm`: 이중 타입이면 모든 sᵍ에 k / |사구체| (= 1/2)를 곱해 총 구동을 단일 수준으로 맞춘다.
- 내 타입, HP, 위력은 냄새에 넣지 않는다.

### 3.5 코드 위치

- `flymon/agent/encode_grid.py`(새 파일): 코드북 로드·검증, `odour()`, `Encoder`와 같은 인터페이스(`odour(battle, move)`, `situation_key`)의 `GridEncoder`.
  `flymon/agent/encode.py`(E0)는 그대로 둔다. 배틀 쪽 선택은 설정으로 한다(M3/M4에서 쓸 때).
- 이 트랙의 생성·측정·규칙 모듈과 실행 스크립트는 새 파일로 만든다(10절). `flymon/brain`은 **호출만** 한다. 호출로 안 되는 변경이 필요하면 구현 전에 사용자에게 묻는다.

## 4. 보정과 짝수 턴 선택

### 4.0 순서 (각 단계 결과는 다음 단계 전에 커밋)

이 스펙 → 레드팀 → 계획 → 구현 → ⓪ 판정 세트 목록 생성·digest 커밋(5.1, 측정 없음) → ① 사구체 단독 구동 측정 → ② 코드북 생성 → ③ 강도 보정 → ④ 작동 특성 기록 → ⑤ 짝수 턴 오라클·선택 → ⑥ 판정.
스모크는 짝수 턴 쌍과 축소 시드로만 한다(판정 세트는 스모크에도 쓰지 않는다). 판정 전에 코드 해시와 요약 사슬 검사를 고정·커밋한다(D8).

### 4.1 사구체 단독 구동 측정 (C3, KC만, 판독 없음)

- 49 사구체 각각을 단독으로 제시 강도 0.35에 제시(settle 800 ms + read 600 ms, H.4 창). 사구체 내 가중은 코드워드와 같은 규약 — sᵍ = c_norm / (그 사구체의 수용체 수), c_norm은 메인 E.1-B·`h3_spec`의 all51 규약(동일 총 ORN 구동)과 같게 둔다. 시드 `24_001_000 + i`, i < 8.
- 기록: 사구체별 KC 스파이크 수(읽기 창), KC 활성 비율. 이 측정은 알파벳(3.1)과 코드북 2차 목적(3.3)에만 쓴다.

### 4.3 강도 s 보정 (KC 활성만, 설정마다)

- 보정 냄새(D5): 배틀에 **나올 수 있는** 상황 냄새 = 단일 타입 상대(풀의 FIGHTING·NORMAL·PSYCHIC·WATER) 8기술 × 4 = 32 + 이중 조합 8기술 × 10 = 80, **112개**(동일 가중, 짝수 턴 쌍과 무관).
  정의: 풀의 상대 타입 집합(단일 4 + 이중 10) × 기술 타입 8. 배틀에서는 양쪽에 같은 종족이 있을 수 있으므로(거울 대전) (FIRE, {FIRE, FLYING})도 포함한다 — 같은 종족을 빼는 쌍 생성기 기준으로는 111개다(기록).
  풀에서 파생하고 테스트로 고정한다. 176개(단일 96 + 이중 80) 기준의 같은 통계는 기록만 한다.
- s ∈ {0.175, 0.25, 0.35, 0.5, 0.7, 1.0, 1.4, 2.0}(D6), 시드 `24_002_000 + i`, i < 8. KC 활성 = 읽기 창에서 한 번 이상 발화한 KC의 비율(메인 G.11과 같은 정의).
- **s의 자격**(D6): 112 × 8 제시의 KC 활성 중앙값 ∈ [0.05, 0.09] **그리고** KC 활성 < 0.03인 제시가 **단일 타입 냄새(32 × 8)에서 ≤ 5% 그리고 이중 타입 냄새(80 × 8)에서 ≤ 5%**.
- **선택 s**(D4): 자격 있는 s 가운데 중앙값이 0.0554에 가장 가까운 값(동률은 작은 s). **자격 있는 s가 하나도 없을 때만** 그 설정은 자격 없음.
- **기록(판정 아님)**: D.6 (a) — 200 ms 이동 창에서 KC 하나라도 150 Hz 초과(메인 G.8 정의)인 제시 수, 5–9% 대역 안 비율, 단일/이중 타입별 중앙값과 3% 미만 비율.
- **ORN 발화율 상한**: `stimuli.present`는 drive = max_rate × strength × sᵍ를 자르지 않는다. 수용체 불응기 상한(`odor_real.cap_hz`와 같은 식)을 넘는 사구체가 있는 제시 수를 기록한다(자르지 않는다 — 엔진 동작 그대로).

### 4.4 짝수 턴 오라클

- **쌍**: `h4_pairs.even_pairs`와 같은 상황(짝수 턴 8개, (a) 18 · (b) 21, 같은 순서), 냄새만 E-grid. 상황 목록은 E0 냄새로 재생성해 `H4Spec.pairs_digest`가 재현될 때만 쓴다.
- **절차**: H.4 그대로 — 엔진 C3(블록 `h4`의 채택 Params), 판독 A = MBON13 / P = MBON05(C3 기본 구획 PPL105·PAM08), z 상수는 블록 `h4`의 값(H.3 기준 집합에서 정의, 인코더 무관),
  α ∈ {0.2, 0.5, 0.8}, 활성 시드 500–507, 선택 시드 600–607, 보고 시드 608–615, 창 800 + 600 ms, 제시 강도 = 4.3의 선택 s.
- **쌍 지표**: `h4_formula`의 식 그대로 — m = min(r, −p), 시험 가능 ⇔ m ≥ 2, 순진 균형 ⇔ |d_pre| < 0.5. T_b = 시험 가능 (b) / 21, F_a = 순진 균형이면서 시험 가능한 (a) 쌍 수.

  순서 **k3-full > k3-norm > k2-full > k2-norm**(사용자 결정 — 사구체가 많아 E0에 가깝고 덧붙인 규칙이 적은 쪽)의 앞.

### 5.3 판독 구간 — 평가 순서 고정 (사용자 결정)

위에서부터 처음 해당하는 줄 하나:

1. (b) 쌍 수 ≠ 21 또는 (a) 쌍 수 ≠ 선언된 n_a(5.1 고정값) → **판독 안 함**(`NOT_READ`).
2. c ≥ 11 → **B_결론없음**: "E0 자체가 이 세트에서 기준을 넘어 인코더 효과로 말할 수 없다."
3. n ≤ c → **B_Tb**.
4. n < 11 → **B_결론없음**: "E0보다 올랐지만 M2 기준에 못 미쳤다."
5. F_a < 2 → **B_Fa**(naive_a와 f_a_possible = naive_a ≥ 2 여부 병기).
6. 그 밖 → **`SELECTED`**.

판정 코드가 권위 있는 원본이다. 산문보다 먼저, n, c ∈ 0..21 × F_a ∈ 0..n_a 전 칸에서 정확히 한 구간이 나오는지(상호 배타·전체 덮음) fixture로 전수 확인하고,
경계(c = 10/11, n = c/c + 1, n = 10/11, F_a = 1/2, (b) 쌍 수 20/22, (a) 쌍 수 n_a ± 1)를 개별 fixture로 둔다.

**무효화(D8)**: 판정 뒤 측정값에 영향을 주는 결함이 발견되면 결과를 `INVALID_RUN`으로 기록하고 **같은 세트로 다시 돌리지 않는다**. 대체 세트는 새 선언(사용자 결정)으로만 정한다.
판정 실행은 ⓪–⑤의 커밋된 코드 해시와 요약 사슬 검사(6절)를 통과해야 시작한다.

## 8. 위험과 알려진 한계

- **사구체 서로소 ≠ KC 서로소**: PN→KC 수렴(KC당 약 6–7 PN 입력)으로 서로 다른 사구체 집합도 KC를 공유한다. 이 설계가 줄이는 것은 입력 수준 공유뿐이다.
- **사구체 수가 적다**: E0의 8–9 대신 2–6 사구체. KC 활성이 대역에 못 닿거나(→ 자격 없음), MBON13 순진 수준이 바닥에 가까워 처벌 쪽(p)이 막힐 수 있다(메인 G.12 분해 1, H.4a.6).
- **구동 불균형**: 단독 사구체 KC 구동이 2–5017(메인 E.1-B, M0c 엔진 기준)로 퍼져 있다. k = 3은 약한 사구체까지 쓴다. 2차 목적(구동 합 균형)이 완화할 뿐 없애지 않는다.
- **선택 편향**: 짝수 21쌍은 G·H·J·K·L·M에서 이미 선택에 쓰였다. 4설정 중 최대를 고르므로 짝수 점수는 위로 치우친다. 판정은 E-grid 키로 선택 쌍과 겹치지 않는 판정 세트(5.1)에서, 별도 시드로만 한다.
- **비교 기준의 의미**: c는 같은 세트의 E0. E0가 그 세트에서 우연히 높으면(c ≥ 11) 결론을 내지 않는다(5.3-2).
- **일반화 없음**: 결합별 학습이라 실제 배틀(M3/M4)에서 셀마다 따로 배워야 한다. 학습 효율 문제는 이 트랙에서 다루지 않는다.
- 오라클은 가소성을 끈 가중치 편집이다(`h4_jobs.oracle_job`). 실제 학습 단계의 제시 유발 억압은 여기에 섞이지 않는다(메인 J.12.9 위험, O.9가 실제 냄새에서는 `SEPARABLE`로 기록).

## 9. 고려했으나 기각한 대안

- **인수별 부호 유지**(어휘·배정·강도만 재설계): E1–E3가 0.14–0.22에 머물렀고 (b) 쌍의 공유 사구체 구조가 남는다.
- **혼합**(결합 부호 + 약한 인수별 채널): 공유 사구체가 다시 생긴다.
- **상성 채널 사전계산**(효과 배율 채널): 주장이 "상성을 배운다"에서 "효과 굉장이 좋다는 것을 배운다"로 바뀐다.
- **B 난수 해시**(시드 고정 난수로 셀마다 k 사구체): 축 쌍이 우연히 사구체를 공유한다(k = 3·N = 40에서 기댓값 약 0.3–0.6개). 판정이 한 번뿐이라 운을 통제할 수 없다.
- **C 실제 냄새 프로파일**(셀마다 Hallem 2006 냄새 하나): 스크래치 실행 가능성 계산(2026-10-01, DoOR.data 커밋 `db323a4`의 `Hallem.2006.EN`, 110 냄새 × 24 수용체, 양의 반응 프로파일 상관):
  상호 r ≤ 0.25인 냄새 집합은 최대 약 10–12개, 8 × 12 격자 단사 할당을 담금질로 찾으면 같은 행·열 864쌍에서 문턱 0.6일 때 위반 0(r 중앙값 0.16, 최대 0.60),
  문턱 0.4일 때 위반 37. 실행은 가능하지만 사구체 겹침을 구조로 0으로 만들지 못하고(24 수용체만 구동, 넓은 반응), P 트랙의 실제 냄새 데이터 영역과 겹친다. 기록만 하고 기각.
