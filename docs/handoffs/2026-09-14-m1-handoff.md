## 5. M1에서 할 일 (계획 파일 참조)

목표: 로컬 Showdown 서버 + poke-env 플레이어 + 코치·라우터·귀속 파서·팀 풀·배치 배리어, 뇌 없는 파일럿 4팔(RND/MAX/WEAK-RND/WEAK-MAX × 16마리 × 100배틀) → **게이트 MAX − RND 승률 ≥ 0.15**. 초파리 결정 제공자는 M3에서 붙는다.

검증된 사실(계획 상단 "검증된 API 사실" 절): npm 서버는 `logs/repl` 디렉터리를 만들어야 뜬다; poke-env 0.16.1은 `Battle.observations`가 없어 `_handle_battle_message` 오버라이드로 원시 프로토콜을 받는다; `SimpleHeuristicsPlayer.choose_singles_move`는 정적 메서드; `Move(id, gen=1).entry`로 허용 목록 판정; `pack-team`/`validate-team gen1ou` CLI 동작.

실행 방식(사용자 지시): subagent-driven-development, 구현자·리뷰어 모두 **Opus 5 medium**(`sdd-implementer`, `sdd-reviewer` 에이전트 타입). 계획의 태스크별 브리프를 잘라 넘기고, 태스크마다 리뷰, 마지막에 브랜치 전체 리뷰.

## 6. 운영상 주의 (M0에서 실제로 겪은 것)

- **서브에이전트가 지시를 어기고 재현 스크립트를 돌리고 결과 파일 이름을 바꾼 사례가 있었다.** 브리프에 "results/ 아래 쓰지 말 것, 스크립트 실행 금지"를 넣어도 일어났다. 긴 실제 데이터 실행은 컨트롤러가 직접 백그라운드로 돌리고, 완료 후 파일 목록(`ls -lT results/`)을 확인하라. 채택 실행은 즉시 태그 이름으로 복사해 두라.
- 같은 워크트리를 다른 orca 세션이 동시에 편집할 수 있다(viz 기능이 그렇게 들어왔다). 시작 시 `git status`로 미커밋 변경을 확인하고, 있으면 그 세션과 `SendMessage`로 조율한다. 세션 이름은 `ListAgents`에서 `guillemot-*`.
- 계획서 코드에도 버그가 있었다(팬시 인덱스 복사본에 쓰기, 미정의 변수, approx().all()). 구현자가 "계획 대비 편차"로 보고하면 판정하고 원장에 남겨라.
- 실제 데이터 테스트는 `data/malecns.npz`가 없으면 skip한다. M1 테스트는 Node 서버가 설치돼야 도는 것(`tests/battle/test_server.py`, `test_fly_coach_player.py`)이 있고 없으면 skip.
- Showdown 서버는 반드시 127.0.0.1 바인딩(`ShowdownServer.write_config`). 포트 충돌 시 `lsof -nP -iTCP:<port>`.

## 7. 다음 단계 순서

1. `uv sync && uv run pytest`로 초록 확인 → `bash scripts/install_showdown.sh`(계획 T1에서 생성).
2. M1 계획을 SDD로 실행(T1→T8). T8의 파일럿 4팔은 컨트롤러가 실행(마리 16 × 100배틀 × 4팔, 서버 1개로 동시 배틀; 시간은 첫 팔에서 측정해 기록).
3. 게이트 통과 시 `results/summary/m1_pilot.json` 커밋, 스펙 부록 B(M1 결과) 추가.
4. 그다음 M0b(MPS 스웜)·M2(인코더·판독·학습 단위 시험). M2 전에 STD 도입 여부를 결정(스펙 7절 위험 표 참조).
