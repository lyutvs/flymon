## 2. M0c에서 확정된 것

- **엔진이 바뀌었다**: `Params.kc_kc_scale = 0.0`이 기본값이고 KC→KC 엣지는 CSC에서 제거된다. `kc_kc_scale = 1.0`이 M0·M0b 엔진이며 CSC가 비트 동일하다(마스크도 곱셈도 하지 않는 분기). 근거: KC 축삭간 접촉은 mAChR-B 매개 억제(Manoim et al. 2022, Current Biology 32:4438)이지 빠른 니코틴성 흥분이 아니다 — lLN1/lLN2와 같은 급의 데이터 라벨 재정의.
- **M0c 게이트 PASS**(D.4 사전 등록, 실행 전 고정): 희소성 6.49% / 4.64%(시드 100–102), Jaccard 0.0252 ≤ 우연 0.0278; MBON 기저 절사 평균 8시드(100–107) 3.14 ± 0.86 Hz; 폭주 — 휴지 8시드 100 Hz 초과 KC 0개, 냄새 B 결정 창 64시드(100–163) 150 Hz 초과 KC **0/64**(최대 118.3 Hz, PN 구동 후각 KC 2개); 등가성 — 옛 엔진이 `results/m0/conditioning.json` 40/40 비트 동일·희소성 차이 0.0·decide 동일, 새 엔진 풀 = 인프로세스(팔 2/2, decide 동일); 처리량 16워커 엔드투엔드 43.2시간 ≤ 60시간.
- **조건화 사전 등록 기준은 실패**(예측대로, 게이트 항 아님): 판정 시드 8–15에서 graded n_flip 6/8, both 평균 −0.288, reversed +1.236, 채널별 특이 억제 7/8. 시드 0–7(보고)은 7/8, both −0.086. MBON13이 한 냄새에만 반응하는 성질(A.4)은 KC→KC와 무관하다.
- **STD는 재보류**. 재검토 조건이 원인명에서 관측치로 바뀌었다(D.6): (a) M2 후보 냄새 창에서 KC 하나라도 200 ms 이상 150 Hz 초과, (b) 같은 턴 후보 간 KC 스파이크 수 비율 > 2, (c) 학습 단위 시험 실패. FR1(330 Hz)·MBON30(300 Hz) 폭주는 판독 core 밖이라 **수용**한다(결정).
- **쓰기 가드**: `kc_kc_scale ≠ 1.0`인 실행이 `results/m0/`, `results/m0b/`, `results/summary/m0.json`·`m0b.json`·`compartments.json`에 쓰려 하면 스크립트가 종료 코드 2로 거부한다(`pool_bench.refuse_old_engine_output`, 경로는 정규화 후 비교). README의 M0 명령은 `--kc-kc-scale 1.0`을 명시한다.
- **요약 작성기**: `scripts/write_m0c_summary.py`가 엔진 정체·표본 수(판정 시드 8–15, 희소성 100–102, 휴지 100–107, 냄새 100–163, 임계 100/150 Hz, 등가성 40건, 워커 {4,8,16})를 검증해 부족 항목을 이름 붙여 거부하고, git 커밋·dirty·입력 sha256을 기록한다. `m0c_gate`의 폭주 항은 표본 수(≥ 8, ≥ 64)를 정의에 포함한다.

## 4. 안 된 것 / 미해결

- **조건화 사전 등록 기준**: M0·M0c 모두 실패. 원인은 판독 core(MBON13)의 편측성이며 엔진 결함이 아니다. M1·M2는 두 채널 합성 지수에 의존하지 않는 판독으로 간다(A.5).
- **PN 입력이 0인 KC 297개**(αβp 95, γd 189)의 역치 정규화는 정의되지 않아 클립 하한(5.2 mV)을 받는다. KC→KC 제거 후 실질 영향이 없어 한계로만 기록했다(D.7). 시각 입력을 쓰는 날 총 흥분 입력 기준 폴백으로 고친다.
- **M3 인터페이스 주의**는 이전 핸드오프 4절 그대로다: `run_in_executor` 단일 스레드, 체크포인트 가중치 fp16 → float32, 시드 커서는 M3 체크포인트, Showdown 배틀 타이머 끄기.
- M1의 벽시계 편차(팔별 33–501초) 원인 여전히 미확인.
- 스펙 6절 `brain/` 줄의 `odors.py`·`readout.py`는 M2 목표 파일(아직 없음).

## 6. 운영상 주의

- 서브에이전트는 `results/` 아래에 쓰지 않는다. 실제 데이터 실행은 컨트롤러가 돌린다. M0c 실행 시간(참고): 희소성 8시드 약 3분, `reproduce --kc-kc-scale 1.0` 939초(3단계와 겹침), 판정 `reproduce` 1279초(겹침), 시드 0–7 486초, 처리량 단독 약 5분. 처리량을 잴 때는 다른 무거운 프로세스를 돌리지 않는다.
- 계획의 코드는 스크래치에서 실행해 검증한 뒤 넣는다. M0c도 그렇게 했고 SDD 실행 중 계획 결함이 없었다(픽스 1라운드는 레드팀이 못 잡은 `--rest-seeds 0` 경로).
- 계획 레드팀(`plan-red-team`)은 이번에도 실질적 발견을 냈다(P0 2건: 옛 경로 덮어쓰기 위험, 게이트 입력 검증 부재).
- 서브에이전트가 API 오류로 중단될 수 있다(이번 세션 2회: 인증 만료, 네트워크). 작업 트리·커밋 상태를 확인하고 "남은 작업을 인계받는" 프롬프트로 재디스패치하면 된다.
- `.superpowers/sdd/`는 git 제외 스크래치. M0c 워크스페이스는 삭제됐다(원장 사본은 세션 스크래치).
